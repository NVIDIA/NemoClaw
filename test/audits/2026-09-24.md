# Test value audit, 2026-09-24

This audit adds a reusable test-value skill, removes duplicated scenarios and obsolete implementations,
and reuses an existing messaging fixture instead of repeating its empty plan fields.
It preserves distinct inputs, negative controls, cleanup checks, and compatibility contracts.

## Scope and method

The repository-wide discovery pass used tracked files at `6c6b3da7009854f5322074071f44e2bf31dc2209`.
The initial coverage baseline used `2e162f266f583d78392494feff44c360d1390ad0`. The audited behavior owners
and shared Launchable fixture are unchanged between those commits.

| Area | Test files | Physical lines |

| CLI source | 1,469 | 508,573 |
| Plugin source | 42 | 14,137 |
| Integration and repository tests | 772 | 290,488 |
| Live E2E | 79 | 36,535 |

| Installer integration | 26 | 16,953 |

| Tool runtime | 1 | 327 |
| Total JavaScript and TypeScript test files | 2,690 | 963,139 |

The audit also inspected two standalone Python test files and three manual shell probe or acceptance
wrappers. Their 189 lines remain unchanged. The five Python tests pass.

Discovery used syntax-aware test-body comparison, similar-body candidates, assertion and helper-call
inspection, imports and consumers, Git history, project routing, and the existing source-shape scanner.
The final exact-body scan found 35 matching groups. Distinct table inputs and different fixture states
accounted for most matches. A broader comparison that ignored literal values produced 232 candidate
groups; embedded scripts and different denial conditions prevent treating those matches as duplicates.

The source-shape scanner reported no unapproved cases and 89 existing reviewed exceptions.
Those security and compatibility exceptions remain. Thirty-four cases without a direct assertion call
were inspected as candidates; throwing helpers, explicit failure callbacks, and nested reporter fixtures
can supply their checks. A repeated serializer call was retained because it checks determinism.

This was a repository-wide discovery audit with manual review of deletion candidates, not a claim that
every test assertion received an independent semantic review. Unproven candidates remain in place.
No live E2E test, assertion budget, coverage threshold, exclusion, or skip was changed.

The initial 710-line cleanup was a mechanical discovery pass, not a completed semantic audit.
The expanded review traced production consumers and replacement paths, inspected test-only module
and export candidates, and compared fixture and assertion responsibilities across these boundaries:

| Boundary | Disposition |
|---|---|
| Onboarding machine and sandbox creation | Remove five unused implementation modules and their suites. Keep active initial/core/final composition tests, transition traces, native/fallback creation, readiness, and process ownership checks. |
| Rebuild, snapshot, and lifecycle actions | Remove the unused in-place session rewind. Keep target-scoped snapshot repair, credential preflight, durable recovery, exact identity, rollback, and cleanup checks. The dormant managed-workload transaction and Hermes clone broker are explicit feature foundations, not accidental leftovers. |
| Inference and policy | Keep separate authentication, transport, endpoint denial, capability, and compatibility cases. The policy failure classifier is exported through the policy facade; absence of direct callers does not justify deleting its contract. |
| Messaging | Reuse `makeMessagingPlan` in 17 test files. Preserve every scenario-specific channel, credential, render, network, and lifecycle input. Keep independent raw schema, parsing, authority, and checkpoint fixtures. |
| Agent runtimes | Keep real Python/shell execution, pairing identity and filesystem-race probes, and per-agent startup and recovery cases. The large auto-pair suite exercises real descriptor and state ownership boundaries. |
| Plugin and package contracts | Keep plugin implementation coverage and compiled CommonJS/package loading contracts. They detect failures that a source-only CLI test cannot. |
| Installer | Keep real installer-process, sourced-function, pipe/TTY, license, and rollback boundaries. Similar inputs at those boundaries are not interchangeable evidence. |
| E2E support and live E2E | Keep workflow authority, image provenance, real systemctl-shim lifecycle, and live fanout contracts. Retain deleted-path selection rows: a Git diff can still name a removed file. Local mocks do not replace live execution evidence. |

The consumer search also retained manifest-loaded GoogleChat/WeChat assets, path-launched private
bridge processes, copied standalone credential-helper security code, and inactive MXC qualification
surfaces. An import-only dead-code rule would incorrectly classify these as removable.

The audit retains the dashboard compatibility-hook test as the only direct exercise of that entrypoint
in its owner suite. Similar CLI and plugin object-guard tests remain because they cover separate
implementations and compilation boundaries. Rebuild and onboarding journal cases remain because their
entrypoints and state differ. Policy cleanup assertions remain across distinct success and failure paths.

Net changes are 1,940 fewer test lines and 440 fewer production lines. No test-support layer was added.
The existing size limits for `nim.test.ts` and `generate-openclaw-config.test.ts` decrease with the files.
Source architecture limits also decrease to reflect the removed root modules and session dependency.
Guidance and this report are counted separately from reductions.

## Validation

- The expanded onboarding selection passed 1,110 cases in 80 files before removal and 1,078 cases
  in 75 files afterward. The five removed coverage modules are the five deleted implementations.
  All remaining branch coverage counts match. One constructor's coverage varied in the combined
  reports; its retained direct transition tests pass, and isolated before/after reports match
  (22/31 statements, 12/14 functions, 8/15 branches, 22/29 lines). No global coverage-equivalence
  claim is made.
- Active creation, stream ownership, rebuild, runtime diagnostics, and workflow checks passed 516
  distinct cases across the focused runs. The final workflow/risk selection run passed all 235 cases.
  The workflow, risk planner, and their tests are unchanged in the final patch.
- All 388 cases in the 17 messaging fixture suites passed before and after consolidation. Their
  names and assertions are unchanged. The after run also included the 233 workflow/risk cases,
  for 621 passing cases in 19 files; the final unmodified selection suites were verified separately.
  An unrelated log-timeout test failed in the initial fixture
  selection; its file was left unchanged and is outside the fixture consolidation.
- The initial published candidate's [CI run](https://github.com/NVIDIA/NemoClaw/actions/runs/36038793942)
  failed one unchanged vLLM-resume case at its five-second timeout. That suite passed in the expanded
  local run. This does not establish that a full hosted rerun passes. Advisor did not run after the
  failed CI gate, and CodeRabbit skipped the draft; neither is review clearance.

- Paired affected-suite runs passed: 743 cases before consolidation and 706 afterward. The retained
  dashboard suite then passed all 16 cases, covering 707 distinct retained cases across the focused runs.
- Ten unchanged source modules have identical covered statement, function, and branch locations in
  the paired reports. The isolated runner comparison also matches all covered locations: 97/129
  statements, 96/138 branches, 15/20 functions, and 91/120 lines. The retained dashboard suite matches
  its baseline coverage. Larger combined runs reported varying runner branch counts, so this audit
  does not claim identical repository-wide coverage.
- The two removed OpenRouter export objects account for two fewer covered initialization statements.
  The adapter's retained branch and function coverage is unchanged.
- The complete non-live macOS run recorded 44,533 passed, 60 failed, and 499 skipped tests across
  2,608 files. None of the changed test files failed. The unchanged dashboard case was retained and
  verified separately after this run. This is not a passing full-suite result.
- Six selected local failures also reproduce on the untouched original baseline: canonical executable
  selection, Portable working-directory reporting, two temporary-path reader checks, and two runtime
  packaging checks requiring GNU tar. Two hard-link cases passed in isolation on the baseline.
  Other full-run failures include timeouts and a Docker bind-mount error; their complete causes were
  not established by this audit. The local environment lacks GNU tar and the broad run used default
  test budgets; the macOS CI workflow configures GNU tools and 60-second test and execution budgets.
- The exact delivery base's [main CI run](https://github.com/NVIDIA/NemoClaw/actions/runs/36026589787)
  passed all 12 CLI shards, plugin tests, and installer integration. Its messaging image construction
  job and aggregate check failed. That image failure is outside this change.
- Test-project membership passed for 2,682 candidates across seven projects. The repository skill
  validator passed all 30 skills, and the standalone Python suite passed five tests.
