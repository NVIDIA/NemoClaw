# Test value audit, 2026-09-24

This audit covers test declarations, their production entrypoints, shared fixtures, standalone probes,
and test-selection metadata. It removes obsolete implementations and abandoned harnesses, consolidates
repeated cases, restores disabled installer checks, and repairs a stale lifecycle-selection owner.
Distinct denial, recovery, cleanup, packaging, and compatibility contracts remain.

## Scope and method

The repository-wide discovery pass used tracked files at `6c6b3da7009854f5322074071f44e2bf31dc2209`.
The initial coverage baseline used `2e162f266f583d78392494feff44c360d1390ad0`. The audited behavior owners
and shared Launchable fixture are unchanged between those commits.

The scope also includes test support and standalone code: the continuation inventory found 392
TypeScript support files (95,045 lines), 34 shell files (9,186 lines), 11 Python files (3,039 lines),
and nine CJS/MTS/CTS files (2,958 lines), before the support cleanup. These are separate from the
test-file counts above. Standalone manual entrypoints remain; uncalled sourceable helpers are removed.

Discovery used syntax-aware test-body comparison, similar-body candidates, assertion and helper-call
inspection, imports and consumers, Git history, project routing, and the existing source-shape scanner.
The baseline exact-body scan found 35 matching groups. Distinct table inputs and different fixture states
accounted for most matches. A broader comparison that ignored literal values produced 232 candidate
groups; embedded scripts and different denial conditions prevent treating those matches as duplicates.

The source-shape scanner reported no unapproved cases and 89 existing reviewed exceptions.
Those security and compatibility exceptions remain. Thirty-four cases without a direct assertion call
were inspected as candidates; throwing helpers, explicit failure callbacks, and nested reporter fixtures
can supply their checks. A repeated serializer call was retained because it checks determinism.

The final publication integrates canonical main `5871fcbcd7a6ae6043e947a32d469068b07a999e` to consume
the current trusted E2E validator dependencies from #12305. Upstream changes are not counted as audit
additions or removals. The assertion-budget conflict was resolved by regenerating the lower budget
from the combined tree; all live entrypoints remain identical to that canonical base.

The whole-tree analysis combines entrypoint reachability, direct consumer and filename searches,
case-body and fixture comparisons, and manual review of candidate contracts and their history.
The continuation maps 4,442 called owners, including 915 owners shared by multiple test files, and
reviews 73 similar-scenario pairs against their actual entrypoints and inputs. This is a structural
and contract audit; it does not claim an independent line-by-line reading of every assertion.
All 79 live test entrypoint files remain byte-identical to the canonical base. No coverage threshold
or exclusion is relaxed and no test is newly skipped. The live assertion budget decreases only for
uncalled helpers; direct live assertion counts are unchanged.

The initial 710-line cleanup was a mechanical discovery pass, not a completed semantic audit.
The expanded review traced production consumers and replacement paths, inspected test-only module
and export candidates, and compared fixture and assertion responsibilities across these boundaries:
