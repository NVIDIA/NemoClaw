# Out of Scope

NemoClaw Agent Configs deliberately excludes the capabilities on this page.
Agent Configs replaces some of them with a different workflow, other components provide some, and others fall outside NemoClaw's responsibilities.
These are product decisions, not unfinished features, so no work is planned to add them to NemoClaw.
For features that Agent Configs does not have yet or has not tested, refer to [Current Limits](limits.md).

The following table gives each exclusion's category, the reason for it, and what to do instead:

| Out of Scope | Category | Reason | What to Do Instead |
|---|---|---|---|
| Backup, restore, snapshot, and transfer commands from NemoClaw v0 | Storage workflow changed | Agent Configs has no equivalent of the NemoClaw v0 `nemoclaw backup-all`, `nemoclaw <name> snapshot create`, `snapshot list`, `snapshot restore`, `upload`, or `download` commands. It uses a mounted-volume workflow instead: files that must survive sandbox replacement go on volumes that the deployment mounts, and storage tools perform backup operations. | [Store agent files on mounted volumes](../build-deploy/state.md#keeping-agent-files-on-mounted-volumes), which preserve them when a sandbox is replaced. Use your storage tools to back up, restore, take snapshots of, and transfer those volumes; mounting a volume does not create a backup. Conversation continuity has [limits for each harness](../build-deploy/state.md#choosing-what-to-retain-for-each-harness). |
| NemoClaw commands for agent-specific actions | Provided by each agent | Each agent and its supporting components define actions such as restarting the agent's own gateway process, and provide the controls for them. NemoClaw relies on those controls instead of reimplementing them. | Use the controls that the agent or component provides; [Ecosystem](../about/ecosystem.md) helps you find the component responsible for each action. Use NemoClaw to preview, apply, export, and remove the deployment as a whole. |
| Step-by-step commands and TypeScript API from NemoClaw v0 | Replaced by desired state | Agent Configs is a new design: you describe the deployment you want in a YAML file, and the CLI, Rust SDK, or OpenTofu provider creates, updates, or removes resources to match it. Agent Configs is not compatible with NemoClaw v0 commands, API, configuration format, or state. | See [which NemoClaw v0 tasks have NemoClaw Agent Configs equivalents](../get-started/migration.md#mapping-the-user-task). |
| Runtime network approval and policy explanation | Provided by OpenShell | NVIDIA OpenShell enforces each sandbox's network policy and provides request approval and policy explanation through its policy advisor. | Use OpenShell's policy advisor. If you approve access through OpenShell, also add it to the deployment YAML as a [named grant](../security/sandbox-network.md#choosing-a-policy), so export and the next apply keep it. Decision: [#12651](https://github.com/NVIDIA/NemoClaw/issues/12651). |
| Named network policy presets | Replaced by named grants | Named grants cover what presets were for: they add specific destinations to the default isolated policy without rewriting the whole policy. | [Add named grants](../security/sandbox-network.md#choosing-a-policy) to the isolated policy, or define them once to [reuse them across sandboxes](../security/sandbox-network.md#reusing-policies-and-grants). Decision: [#12651](https://github.com/NVIDIA/NemoClaw/issues/12651). |
| Shields, the NemoClaw v0 lock on agent configuration and state | Outside NemoClaw's core | Locking agent state after setup is an optional capability for other products. Keeping it in NemoClaw would add security, recovery, and testing work for every supported agent. | No replacement is provided. NVIDIA OpenShell still enforces sandbox isolation and network policy. Decision: [#10696](https://github.com/NVIDIA/NemoClaw/issues/10696). |
| Automatic conversion of a NemoClaw v0 deployment and its data | No state adoption | Agent Configs uses a new state format and does not take over resources that it did not create. Each agent owns its data format, so Agent Configs does not convert agent data. | Run Agent Configs as a [separate deployment](../get-started/migration.md#keeping-deployment-identities-separate) beside NemoClaw v0. [Author YAML with onboarding](../get-started/onboard.md) or [start from a configuration export](../get-started/migration.md#starting-from-the-earlier-export) if your NemoClaw v0 CLI supports it. [#14580](https://github.com/NVIDIA/NemoClaw/issues/14580) tracks agent-assisted migration. |
