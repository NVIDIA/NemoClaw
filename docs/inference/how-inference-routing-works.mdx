NemoClaw gives agents a managed inference path while OpenShell handles the selected upstream provider on the host.
This design keeps provider credentials outside the sandbox.

## Request Path

New NVIDIA Endpoints, OpenAI, Anthropic, Google Gemini, OpenRouter, and Hermes Provider selections use sandbox-attached OpenShell providers.
The agent calls the selected provider's API hostname with a credential placeholder.
OpenShell checks the destination, executable, and allowed request paths, then supplies the host-managed credential.

```text
Sandbox agent -> provider API hostname -> sandbox-attached OpenShell provider -> selected hosted service
```

| Provider | Agent endpoint |
| --- | --- |
| NVIDIA Endpoints | `https://integrate.api.nvidia.com/v1` |
| OpenAI | `https://api.openai.com/v1` |
| Anthropic | `https://api.anthropic.com` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Hermes Provider | `https://inference-api.nousresearch.com/v1`, or the endpoint returned by authenticated login |

Each sandbox records its selected provider attachment. Changing one sandbox's native selection does not change another sandbox's route.
OpenRouter attribution headers remain in the managed agent configuration.
For an endpoint returned by Hermes login, NemoClaw records its accepted public IP addresses and restricts the provider and sandbox policy to those addresses.
A different destination cannot gain access through a later DNS change.

Existing sandboxes without a native attachment retain their recorded shared route.
Legacy local routes have the recovery restrictions described under [Credential Boundary](#credential-boundary).
New Deep Agents Code, Hermes, OpenClaw, and Pi selections for Ollama, standalone vLLM, and llama.cpp use sandbox-attached providers for qualified host-local endpoints.
Deep Agents Code, Hermes, and Pi also use attached providers for qualifying host-local compatible endpoints.
Qualifying custom hosted endpoints use sandbox-attached providers.
Local NVIDIA NIM, remaining shared custom selections, Model Router, and unchanged published Pi shared local selections retain the shared route.
Shared `inference.local` routes require OpenShell `0.0.x`.
OpenShell `0.1.3` removes that route; migration of the remaining selections is incomplete and blocks this upgrade.
Native local onboarding on `0.1.3` remains unqualified for this upgrade.
Hermes live qualification for the new local lifecycle remains pending.

```text
Sandbox agent -> inference.local -> shared OpenShell route -> selected provider and model
```

Use `$$nemoclaw inference get` to inspect the selected sandbox's recorded route.
`status`, `doctor`, and startup checks verify its recorded native provider identity before using a native attachment.
Missing or conflicting ownership stops the operation instead of falling back to the shared route.

<AgentOnly variant="hermes">
Hermes native local provider profiles include the pinned image's resolved Python interpreter, `/usr/bin/python3.13`.
An older imported profile that lacks this executable can conflict with the current profile definition.
NemoClaw stops and leaves an incompatible existing profile unchanged.
Preserve the profile and provider while a NemoClaw maintainer reviews their ownership and attached sandboxes and chooses an explicit replacement plan.
Retry only after the profile conflict is resolved.
</AgentOnly>

## Credential Boundary

Provider credentials stay on the host and flow through the OpenShell provider system.
The sandbox does not receive the raw upstream API key.

Local Ollama and local vLLM routes do not require the host `OPENAI_API_KEY`.
NemoClaw uses provider-specific local tokens for those routes.
For retained shared local routes, rebuilds migrate away from stale OpenAI credential requirements.
Legacy Deep Agents Code local sandboxes without an attachment require a backup and fresh recreation.
On OpenShell `0.0.x`, existing OpenClaw Ollama, standalone vLLM, and llama.cpp sandboxes without an attachment retain supported shared-route model switches.
They cannot resume or rebuild.
Back one up and re-onboard with `--fresh --name <sandbox-name> --recreate-sandbox`.
Owned Local NVIDIA NIM sandboxes can resume or rebuild on their shared route with OpenShell `0.0.x`.
Legacy Hermes Ollama, standalone vLLM, llama.cpp, and qualifying host-local compatible routes without a native attachment cannot resume or rebuild.
Back up required sandbox state before running `nemohermes onboard --fresh --name <sandbox-name> --recreate-sandbox` to replace the sandbox with a native attachment.
Owned Local NVIDIA NIM and remaining custom shared selections retain their shared route on OpenShell `0.0.x`.
For an attached Hermes route, startup refreshes the credential reference before starting the gateway.
Rebuild refreshes only the restored credential references, preserving the selected model and provider settings.
When a rebuild reuses an automatically bridged compatible-endpoint route without a host API key, NemoClaw reapplies the config-only bridge rewrite without reading or passing the credential stored in OpenShell.

## Deep Agents Configuration

For Deep Agents, NemoClaw writes `/sandbox/.deepagents/config.toml` with a managed OpenAI-compatible provider, a scoped placeholder API key, and `use_responses_api = false`. Supported native hosted selections use the endpoints above. New Ollama, standalone vLLM, llama.cpp, and qualifying local compatible selections use their qualified host-local endpoint through an attached provider. Owned Local NVIDIA NIM and other shared-route selections retain `https://inference.local/v1`.
The managed `dcode` runtime uses Chat Completions through OpenShell even when a compatible endpoint also supports the Responses API.

</AgentOnly>
