Move a sandbox to another provider family while keeping the OpenShell route, agent configuration, and host registry aligned.
Runtime switching accepts catalog providers and qualifying providers already registered on the selected sandbox's OpenShell gateway.
Use onboarding to configure a provider that is supported by onboarding but unavailable for runtime switching.
The compatible endpoint workflow below can register an absent custom provider from complete route metadata.

<AgentOnly variant="openclaw,hermes">

## Choose a Supported Provider

List the configured provider credentials when you need the provider ID.

```bash
$$nemoclaw credentials list
```

`inference set` also accepts installer-facing provider names such as `anthropicCompatible`, `build`, `custom`, and `llama-cpp`.
It accepts recognized underscore spellings of canonical provider IDs and hyphenated aliases, such as `ollama_local`, `nvidia_prod`, and `open_router`.
NemoClaw normalizes an accepted alias or underscore spelling to its canonical OpenShell provider ID and records the canonical name in the sandbox registry.

The legacy hosted alias `nvidia-nim`, including `nvidia_nim`, selects NVIDIA Endpoints and normalizes to `nvidia-prod`.
The installer names `nim`, `nim-local`, and `nim_local` select Local NVIDIA NIM through `vllm-local`.
This local selection requires the NIM container and endpoint recorded for the sandbox or a matching onboarding session.
The endpoint must match the NIM runtime, and that runtime must serve the requested model.
Missing or inconsistent NIM state stops the switch before mutation; it does not select hosted NVIDIA Endpoints or standalone vLLM.
Rerun onboarding for the affected sandbox with `NEMOCLAW_PROVIDER=nim-local` to repair its recorded selection, then retry the switch.
Endpoint, API-family, and credential overrides do not apply to this local selection.

If a provider is outside the catalog, NemoClaw checks for its exact name on the selected sandbox's verified gateway.
An unavailable inventory or an absent provider stops the switch before mutation.
Messaging providers cannot be selected for inference.

If OpenShell cannot find a requested catalog provider other than `compatible-endpoint` or `compatible-anthropic-endpoint`, NemoClaw leaves the route and sandbox state unchanged.
Run `$$nemoclaw onboard` to register the provider, then retry the switch.
For a compatible custom endpoint, pass the complete route metadata described below so NemoClaw can register the provider.

### Select an Existing Registered Provider

Use the existing provider's name with the runtime switch command below.
Provide its endpoint, API family, and credential environment variable through the native agent configuration or the corresponding command options.
Use `--endpoint-url`, `--inference-api`, and `--credential-env` only for metadata that agrees with the existing configuration.
The endpoint must use HTTPS, including operator-managed private endpoints.
NemoClaw rejects HTTP before attaching the provider or reading its credential handle.
Retained HTTP records remain readable for inspection and removal of NemoClaw-created attachments, but NemoClaw refuses to resume credential use through those endpoints.
Every profile endpoint matching the selected host and port must use `protocol: rest` and explicit `enforcement: enforce`.
Each matching endpoint's `tls` field must be omitted or an empty string to retain automatic TLS inspection.
Its `allow_uninspected_credentials` field must be omitted or `false`.
NemoClaw refuses selection and credential use when these checks fail.
Identity inspection and removal of NemoClaw-created attachments remain available, subject to identity and ownership checks.
The profile's existing rules, access mode, and IP restrictions remain operator-controlled.
NemoClaw verifies the provider identity and its declared profile against the selected endpoint and authentication method before attaching it to the sandbox.
Missing or conflicting metadata stops the switch.

The credential value remains with OpenShell.
NemoClaw reads the selected sandbox's OpenShell credential handle, verifies the attachment again, and writes that handle into the agent configuration.
It does not import raw credentials or accept authentication-header overrides from the native configuration.
The existing provider and its credentials remain operator-owned; switching does not update or delete them.

The switch uses the native endpoint without changing the shared inference route.
After switching, confirm the provider and endpoint with `$$nemoclaw <name> inference get`.
Run `$$nemoclaw <name> status` to verify inference health.
If verification fails before the selection is committed, NemoClaw attempts to remove only its newly created attachment and restore the previous selection.
A target attachment that existed before the switch is retained.
If cleanup or restoration cannot be confirmed, resolve the reported failure before retrying.

</AgentOnly>

## Switch the Provider at Runtime

Pass the target provider and model together.
Target a non-default sandbox by name.
`inference set` takes `--sandbox <name>`.

```bash
$$nemoclaw inference set --provider <provider> --model <model> --sandbox <name>
```

For native NVIDIA and fixed hosted providers, NemoClaw updates only the selected sandbox attachment and verifies a request through its native endpoint. A hosted compatible endpoint uses a native provider during a runtime switch only when the sandbox already records a valid native attachment; a retained shared-route sandbox keeps its route only on OpenShell `0.0.x`. OpenClaw also keeps model switches on a recorded native Ollama, standalone vLLM, or llama.cpp attachment within that sandbox.
OpenRouter requests include its attribution headers.
If sandbox verification fails, NemoClaw tries to restore the previous inference selection and does not commit the agent configuration.

</AgentOnly>

<AgentOnly variant="openclaw">

For OpenClaw, NemoClaw updates the provider namespace and selected model in the running configuration.
It adds or updates the requested model entry without removing other model entries in that provider.
For NVIDIA Endpoints, native hosted providers, and native local providers, it writes the attached provider's scoped OpenShell credential reference into the native configuration.
This reference is not a raw provider credential.
When switching to a different Ollama, standalone vLLM, or llama.cpp provider, NemoClaw prepares and attaches a provider for the selected local runtime.
The switch verifies existing attachment ownership and leaves the shared route unchanged.
Existing shared-route local sandboxes that keep the same provider can still use supported model switches on OpenShell `0.0.x`.
Older Ollama, standalone vLLM, and llama.cpp sandboxes without an attachment cannot resume or rebuild.
Back them up and re-onboard with `--fresh --name <sandbox-name> --recreate-sandbox`.
After any changed configuration sync, NemoClaw restarts only the OpenClaw gateway and verifies its health.
The sandbox remains running, but agent requests are briefly interrupted.
After every changed synchronized route, NemoClaw verifies that the local CLI device has the managed gateway's required pairing scopes before it reports success.
If the restart fails, the route and configuration remain committed.
Run `$$nemoclaw <name> gateway restart` to apply the committed configuration.
If pairing does not converge, the route and configuration remain committed.
For `initial-state-unavailable` or `final-state-unavailable`, use the observation failure category in the error and audit entry to diagnose the failed check.
The category does not include raw observer output, pairing state, or credentials.
Run `$$nemoclaw <name> doctor --fix`, then retry the agent turn.

</AgentOnly>

<AgentOnly variant="hermes">

For Hermes, NemoClaw updates the native `/sandbox/.hermes/config.yaml`, including the model, base URL, API-family mode, and managed API-key value.
Ollama, standalone vLLM, llama.cpp, and qualifying host-local compatible selections use sandbox-attached providers without changing the shared route.
Qualifying custom hosted endpoints also use sandbox-attached providers.
Remaining custom shared selections retain `inference.local` on OpenShell `0.0.x`.
A legacy local sandbox without a valid Hermes attachment must be recreated before a native local switch: back up required state, then run `nemohermes onboard --fresh --name <sandbox-name> --recreate-sandbox`.
Live qualification of the Hermes native local lifecycle is pending.
`inference.local` uses the OpenShell proxy rewrite sentinel.
Generated NVIDIA Build configuration uses `${NVIDIA_INFERENCE_API_KEY}` for supervisor expansion.
A live switch to NVIDIA Build or a qualified local provider writes the newly attached provider's scoped OpenShell credential reference.
These values do not expose the raw provider credential.
The gateway, CLI, TUI, and Web Dashboard all read that shared configuration.
Changes between shared routes do not rebuild or restart Hermes.
If the current or selected route uses a native hosted or local provider, NemoClaw restarts the Hermes gateway after configuration sync.
Active agent requests can be interrupted during the restart.
If the restart fails, the route and configuration remain committed.
Run `$$nemoclaw <name> gateway restart` to apply the switch.

</AgentOnly>

<AgentOnly variant="openclaw">

If NemoClaw cannot confirm the native OpenClaw config batch, the OpenShell route and host registry remain committed, but `inference set` exits nonzero.
Rerun the same `inference set` command to converge the config.
A rebuild restores the previous native `openclaw.json`, so it does not repair this failure.

</AgentOnly>
<AgentOnly variant="hermes">

If the in-sandbox configuration sync fails after the gateway route changes, NemoClaw keeps the gateway and host registry aligned.
For an existing registered provider, retry the same `inference set` command to finish configuration sync.
For other providers, follow the printed rebuild hint before relying on the running agent.

</AgentOnly>
<AgentOnly variant="openclaw,hermes">

Use `--no-verify` only when OpenShell cannot verify the target provider at switch time and you have already confirmed its provider and credential.
This flag does not bypass shared-gateway compatibility checks.
NemoClaw rejects an unverified custom route that uses `host.openshell.internal` because the alias and port do not prove which host process owns the destination.
Qualified OpenAI-compatible native-local routes and managed adapter routes retain their recorded host bridge endpoint.
Use a public endpoint or an explicitly trusted private hostname or IP address.
The output limit is 16 tokens for ordinary providers and 256 tokens for Google Gemini.
Before sandbox verification, NemoClaw waits 6 seconds when the provider, model, or provider attachment changes.
This wait also applies when a custom endpoint change replaces the attachment but keeps the provider and model names.
When the switch also changes the API family and that request returns HTTP `400` or `404`, NemoClaw retries up to two times after delays of 2 and 4 seconds.
NemoClaw uses the same retry schedule when validation fails before it receives an HTTP status, such as while the gateway route is reloading.
Each retry uses the same output limit for the selected provider.
Other HTTP failures are not retried.
If that request fails, NemoClaw attempts to restore the previous OpenShell selection and remove a provider that this switch created.
If the error reports that rollback could not complete, rerun onboarding before using the route or retrying the switch.
Endpoint-shape and shared-gateway compatibility checks still apply.

</AgentOnly>

## Handle Compatible Endpoints

When moving from another provider family to `compatible-endpoint` or `compatible-anthropic-endpoint`, provide the trusted endpoint URL and enough API metadata to record the complete route identity.
Export the canonical credential environment variable for the target provider.
Run this command from the host that owns the sandbox.

```bash
export COMPATIBLE_API_KEY="<api-key>"
$$nemoclaw inference set \
  --provider compatible-endpoint \
  --model <model-name> \
  --endpoint-url <trusted-url> \
  --credential-env COMPATIBLE_API_KEY \
  --inference-api openai-completions \
  --sandbox <name>
```

NemoClaw validates the endpoint before it changes the route.
For a custom compatible endpoint that uses a native provider, NemoClaw reads the sandbox's base policy before creating or detaching a provider.
When the provider pins destination addresses, existing endpoint rules that cover its host and port must have matching IP pins.
This includes wildcard host rules and IP-only rules on that port.
If the pins are absent or differ, the command names the conflicting policy and leaves providers and the inference selection unchanged.
{/* This page is published under inference/manage-inference; links follow the navigation slugs in docs/index.yml. */}
Follow [Customize the Sandbox Network Policy](../../network-policy/customize-network-policy) to inspect the named rule before retrying.
If NemoClaw cannot read the policy, resolve the reported OpenShell error before retrying.
For an HTTPS IP-literal or DNS-pinned HTTP endpoint, NemoClaw registers and verifies an absent provider before selecting the route.
If OpenShell still reports the provider as absent, NemoClaw retries the switch once.
If provider verification fails or OpenShell confirms that it did not apply the route, NemoClaw leaves the inference selection unchanged.
If OpenShell cannot confirm whether it changed the route, NemoClaw stops and reports an unknown result.
Run `$$nemoclaw <name> inference get` to inspect the selected sandbox's gateway before you use the route or retry.
NemoClaw removes the provider only when it can verify the revision created by this switch.
If removal was not attempted or could not be confirmed, rerun onboarding before using that provider route or retrying the switch.
For a DNS-backed HTTPS endpoint, NemoClaw registers the HTTPS Pin Runtime provider before the first route attempt.

Supported API-family values are `openai-completions`, `anthropic-messages`, and `openai-responses`.
For a Hermes `compatible-anthropic-endpoint` target, omit `--inference-api` because NemoClaw selects `openai-completions`.
An explicit different API family is rejected for that route.

To switch only the model for an existing compatible provider, omit the endpoint options.
NemoClaw reuses the endpoint in the sandbox registry and verifies the selected route.
To change a direct compatible provider's custom endpoint or credential binding, re-run onboarding with the requested binding.
`inference set` refuses to replace an existing direct binding because OpenShell does not expose the previous provider configuration required for rollback.
A rebuild reuses the recorded endpoint and cannot change it.

DNS-backed HTTPS routes use an HTTPS Pin Runtime binding.
Provider updates occur after OpenShell selects the new route.
If sandbox verification fails after an existing provider update succeeds, NemoClaw restores the previous inference selection but leaves the updated provider binding in place.
Rerun onboarding before using that provider route or retrying the switch.
If an update fails, NemoClaw attempts to restore the previously recorded provider and model.
If NemoClaw rejects the update before the provider command runs, the provider binding stays unchanged.
After a provider command fails without confirming that no change occurred, provider state may be partial.
If the error says that provider state may be partial, rerun onboarding to reconcile the provider before using the route or rerunning `inference set`.
If NemoClaw cannot restore the previous selection, resolve the reported restore failure.
Then rerun onboarding before you use the route.

</AgentOnly>

## Account for Shared Gateways

One gateway has one live route even when NemoClaw records different intended routes for its sandboxes.
Review [Use Shared Gateway Routes](use-shared-gateway-routes) before changing a provider that another registered sandbox shares.
For a shared-route switch, provider-global endpoint, API-family, credential, and incomplete-metadata conflicts stop the command before mutation.
Native hosted attachments, qualified Hermes local attachments, and recorded OpenClaw native local attachments do not change that shared route.
