NemoClaw can connect to an existing vLLM server or install and start a managed vLLM container on supported NVIDIA GPU hosts.

<Note>
NemoClaw forces the Chat Completions API path for vLLM.
The vLLM `/v1/responses` endpoint does not run the configured tool-call parser, so tool calls can arrive as raw text.
</Note>

<Warning>
Local vLLM does not require authentication by default.
NemoClaw needs port `8000` on host loopback for validation and on the OpenShell Docker bridge for sandbox traffic.
Use a host firewall with default-deny inbound rules.
Allow TCP port `8000` only from the OpenShell Docker subnet to its gateway address, keep loopback access, and deny the port on every other interface.
Do not expose the port to your LAN or the internet.
</Warning>

## Use an Existing Server

When vLLM is already running on `localhost:8000`, NemoClaw detects it and queries `/v1/models` for the loaded model.

Run onboarding.

```bash
$$nemoclaw onboard
```

Select **Local vLLM**.
On generic hosts, the entry includes an experimental label; on DGX Spark or DGX Station, it does not.
NemoClaw validates the detected endpoint and records the model reported by `/v1/models`.
When vLLM exposes runtime metadata such as `max_model_len`, NemoClaw uses that value for the configured context window unless you set `NEMOCLAW_CONTEXT_WINDOW`.

Start vLLM with the model you want before onboarding because NemoClaw uses the model already served by the endpoint.

<Warning>
On DGX Spark, an existing vLLM server is operator-managed.
NemoClaw warns when vLLM metadata heuristically indicates a large checkpoint without reported quantization, does not identify the underlying model size, or reports an unusually long context window.
These configurations can leave too little unified-memory headroom for the host and surface as `NVRM NV_ERR_NO_MEMORY`, SSH loss, or a hard host freeze under agent/tool load.
Prefer the managed Spark vLLM path when you want NemoClaw to use the validated Spark recipe, or restart your existing server with lower `--gpu-memory-utilization`, `--max-model-len`, `--max-num-seqs`, and `--max-num-batched-tokens` before onboarding.
For full diagnostics and recovery steps, refer to [DGX Spark troubleshooting](../../reference/troubleshooting#dgx-spark).
</Warning>

## Configure Structured Tool Calls

Start vLLM with automatic tool choice and the tool-call parser that matches the model family when the model serves a tool-using agent.
For a Hermes 3 style model, use this command shape.

```bash
vllm serve /models/Hermes-3-Llama-3.1-8B \
  --served-model-name hermes-3-llama-3.1-8b \
  --enable-auto-tool-choice \
  --tool-call-parser hermes \
  --host 0.0.0.0 \
  --port 8000
```

Use the parser required by your selected model instead of copying `hermes` for another model family.
Without both `--enable-auto-tool-choice` and a matching parser, tool calls can appear as raw assistant text instead of structured `tool_calls`.

## Install or Start Managed vLLM

NemoClaw displays the **Install vLLM** or **Start vLLM** entry by default on DGX Spark and DGX Station.
Generic Linux NVIDIA GPU hosts require `NEMOCLAW_EXPERIMENTAL=1` or `NEMOCLAW_PROVIDER=install-vllm` before the managed entry appears.

In an interactive run, the managed path lists the supported model registry for your host profile.
Press **Enter** to use the profile default or select another validated model with its registered `vllm serve` arguments.

NemoClaw resolves the pinned vLLM image, downloads model weights into `~/.cache/huggingface`, starts the `nemoclaw-vllm` container on `localhost:8000`, streams Hugging Face download progress, and polls `/v1/models` until the model is ready.
Registry-backed recipes pull that image; a local-only profile requires its exact image to be preloaded.
The container carries a NemoClaw ownership label so later onboarding runs can distinguish it from a bring-your-own server without trusting the container name alone.
If an existing `nemoclaw-vllm` container does not carry that label, NemoClaw preserves it and asks you to remove or rename it before installing managed vLLM.
If another vLLM server already occupies port `8000`, the managed path stops and asks you to select the existing server or stop it first.
Managed profiles and model-specific recipes use immutable image digests:

- DGX Spark and DGX Station models without a model-specific runtime use the `linux/arm64` digest `sha256:9204569b17ee4c0eff75194b8e6e458479c8aee18953b5ab9cf359fcdac659e2` with a compressed layer size of `9.60 GB` under `nvcr.io/nvidia/vllm:26.05.post1-py3`.
- The canonical DGX Station Nemotron 3 Ultra express recipe uses the multi-platform index digest `sha256:0fec7ec5f3e6bc168e54899935fb0557da908a4832a1dbc88e2debcf2f889416` under `vllm/vllm-openai:v0.22.0`; on DGX Station, that index selects a `linux/arm64` manifest with a compressed layer size of `10.67 GB`.
  It also pins Hugging Face revision `183968f87ae4cedce3039313cac1fd43d112c578` for the approximately `352.38 GB` model download.
- The opt-in DGX Station `experimental-single-user` profile requires the preloaded local image ID `sha256:e44830d3f0197850e5a63ca895b13a047f358ff4aea15b1655abf61391bb883e`.
  This ID is not currently published as a pullable repository manifest, and no existing registry tag has been proven to resolve to it.
  NemoClaw does not substitute the canonical Ultra image or another vLLM image when the qualified image is absent.
- Generic Linux `arm64` hosts use `sha256:447995cbb57e6c7cf792cab95e9852e5f62b5fb6d2f39e030fa4eda9a54eadb4` with a compressed layer size of `9.28 GB` under `nvcr.io/nvidia/vllm:26.03.post1-py3`.
- Generic Linux `amd64` hosts use `sha256:7be6c2f676c36059a494fe17254e69ae5c677535ba6191044e5fc8e42a91c773` with a compressed layer size of `8.93 GB` under `nvcr.io/nvidia/vllm:26.03.post1-py3`.

Image pulls from `nvcr.io` require NGC registry login.
The canonical Station Nemotron 3 Ultra recipe pulls its vLLM image from Docker Hub instead.

The first run duration depends on image and model size, storage performance, and network throughput.
Later runs reuse the cached image and model weights.
The managed container uses Docker's `--restart unless-stopped` policy, so Docker restarts it unless an operator explicitly stops it.

### Check Storage Before the Image Pull

For an uncached pinned image, NemoClaw checks Docker image storage before the watched image pull starts.
The estimate reserves three times the image's compressed registry size plus `3 GiB` for compressed content, unpacked layers, and pull staging.

For Docker's classic image store, NemoClaw checks the absolute `DockerRootDir` reported by `docker info`.
For Docker's containerd image store, it checks the top-level `root` from `/etc/containerd/config.toml`, or `/var/lib/containerd` when that configuration file is absent, and also checks `DockerRootDir` for pull staging.
The check uses the location with the least available capacity.

For registry-backed recipes, NemoClaw recognizes an image cache hit only when Docker contains the exact platform digest.
A registry-backed cache hit skips the capacity check, but the explicit watched `docker pull` still runs against that immutable digest.
The local-only experimental profile performs no pull and verifies the qualified image ID directly.
The model-download helper and the long-lived vLLM container use `--pull=never`, so an implicit pull cannot select another image.

NemoClaw treats `/var/run/docker.sock` and `/run/docker.sock` as the local default Docker socket paths.
It cannot inspect daemon storage through a remote endpoint, a named non-default Docker context, or another Unix socket.
When both `DOCKER_CONTEXT` and `DOCKER_HOST` are set, NemoClaw follows Docker CLI precedence and uses `DOCKER_CONTEXT`.
Before a registered model with pinned size metadata is downloaded, NemoClaw also checks the filesystem that contains the host Hugging Face cache.
When either check is inconclusive, NemoClaw prints the reason, approximate requirement, and diagnostic commands, then continues without claiming that capacity is sufficient.

When verified capacity is insufficient, the warning identifies the image, available capacity, approximate requirement, checked path and source, remediation, and diagnostic commands.
Interactive setup continues only when you enter `y` or `yes` explicitly.
Pressing **Enter**, entering `n` or `no`, or entering any other response stops before the guarded image or model download starts.

<Warning>
`--yes` and `NEMOCLAW_YES=1` do not accept a verified insufficient-storage warning.
Non-interactive setup stops unless you set `NEMOCLAW_IGNORE_VLLM_DISK_SPACE=1` exactly.
The override applies only when NemoClaw verifies that Docker image storage or model-cache storage is insufficient.
Use it only after you independently verify that the relevant filesystem can complete the download.
Inconclusive checks continue automatically and do not require the override.
</Warning>

<Note>
The model-cache guard applies when the selected registered recipe declares a pinned snapshot size.
NemoClaw creates `~/.cache/huggingface` as the host user and runs the one-shot download container with the host UID and GID, avoiding root-owned cache paths.
Hugging Face credentials are forwarded only to that temporary downloader, not retained by the long-lived vLLM container.
A legacy root-owned or otherwise unwritable cache stops before the image pull and prints a safe ownership-repair command; NemoClaw never changes its ownership automatically.
</Note>

If image pull output stops making progress, a watchdog stops the stalled pull without imposing a fixed wall-clock limit on slow but active downloads.
If vLLM does not become ready, NemoClaw prints a short tail of the container logs before exiting.

When you start managed vLLM outside the installer express flow, NemoClaw uses these profile defaults:

| Host profile | Default model |
|---|---|
| DGX Spark | `nvidia/Qwen3.6-35B-A3B-NVFP4` |
| DGX Station | `deepseek-ai/DeepSeek-V4-Flash` |
| Linux with an NVIDIA GPU | `nvidia/NVIDIA-Nemotron-3-Nano-4B-FP8` |

On DGX Station, accepting the installer express prompt sets `NEMOCLAW_VLLM_MODEL=nemotron-3-ultra-550b-a55b` and overrides the profile default.
Pass `--station-deepseek` to select the existing `deepseek-v4-flash` recipe while retaining the same one-confirmation express flow.
The registered Ultra recipe tracks the [official DGX Station deployment guide](https://github.com/NVIDIA-NeMo/Nemotron/blob/287ae845639d2ce998998cb8fd1f70a3fa943c0b/usage-cookbook/Nemotron-3-Ultra/StationDeploymentGuide/README.md) and configures the pinned model revision, CPU offload, `16 GB` of shared memory, memory/stack ulimits, MTP speculative decoding, and the Nemotron reasoning and tool-call parsers.
NemoClaw intentionally keeps its existing bridge-networked managed-inference topology instead of importing the playbook's host-network setting.
The container publishes port `8000` through Docker, so apply the firewall guidance at the top of this page.

### Opt In to the Experimental Single-User Station Profile

The `experimental-single-user` profile extends the existing managed-vLLM and Station express lifecycle; it is not a separate launcher.
It is explicit opt-in and does not change the canonical Station express recipe above.
The canonical recipe remains the default while Nemotron-team quality validation of this experimental profile is pending.
Use it only on a detected DGX Station:

```bash
curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash -s -- --station-experimental-single-user
```

The installer maps this flag to `NEMOCLAW_VLLM_PROFILE=experimental-single-user` and rejects conflicting model, profile, extra-argument, DeepSeek, and non-Station selections.
An inherited profile selector cannot silently change the ordinary Station express prompt: use the flag for installer express, or pair the profile and model selectors with `NEMOCLAW_PROVIDER=install-vllm` for advanced direct onboarding.
It also rejects ambient `NEMOCLAW_VLLM_PORT` values other than `8000`, `NEMOCLAW_CONTEXT_WINDOW` values other than `262144`, and `NEMOCLAW_LOCAL_INFERENCE_SANDBOX_HOST_URL` routes other than `http://host.openshell.internal`, so host readiness, gateway routing, and the dashboard cannot drift from the qualified contract.
An existing server on port `8000` is not reused for this profile; stop it before opting in so the existing managed-vLLM lifecycle can prove the qualified image, arguments, environment, and hardware limits.

<Warning>
The qualified runtime exists today only as local Docker image ID `sha256:e44830d3f0197850e5a63ca895b13a047f358ff4aea15b1655abf61391bb883e`.
Before running the installer, this command must return that exact ID:

```bash
docker image inspect -f '{{.Id}}' sha256:e44830d3f0197850e5a63ca895b13a047f358ff4aea15b1655abf61391bb883e
```

A fresh pull or fresh machine install remains blocked until a repository-qualified manifest pin is published and proven to resolve to the qualified image.
The profile fails closed instead of silently using a different vLLM image.
</Warning>

The profile uses the reclaimed-v1/offload90 configuration with this model identity:

| Setting | Value |
|---|---|
| Hugging Face model | `nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-NVFP4` |
| Revision | `183968f87ae4cedce3039313cac1fd43d112c578` |
| Served model | `nemotron-ultra` |
| Maximum context | `262144` |

Its container runs with host networking and host IPC, `16 GiB` shared memory, a `650 GiB` container memory limit, tensor parallel size `1`, and a `1200`-second startup timeout.
Because the qualified contract binds the unauthenticated vLLM API to `0.0.0.0:8000` on the host network, apply the default-deny firewall rules at the top of this page before opting in; this profile does not install or modify host firewall rules.
The installer fails closed unless exactly one GB300 is available, HBM is below `245000 MiB`, and aggregate and volatile uncorrected ECC are zero before launch; it samples the same exclusive HBM ceiling and ECC contract throughout startup.
Full workload-level HBM/ECC qualification through chat and tool calls remains part of the blocked current-PR physical Station acceptance run.

After `vllm serve` and the pinned revision's local snapshot path, the profile supplies exactly these vLLM arguments:

```text
--served-model-name nemotron-ultra
--host 0.0.0.0
--port 8000
--tensor-parallel-size 1
--trust-remote-code
--cpu-offload-gb 90
--cpu-offload-params experts
--kernel_config '{"enable_flashinfer_autotune": false}'
--max-num-seqs 1
--gpu-memory-utilization 0.9
--kv-cache-memory-bytes 4294967296
--reasoning-parser nemotron_v3
--enable-auto-tool-choice
--tool-call-parser qwen3_coder
```

The required environment is:

```text
VLLM_WEIGHT_OFFLOADING_DISABLE_PIN_MEMORY=1
VLLM_NVFP4_GEMM_BACKEND=flashinfer-trtllm
NEMOTRON_ULTRA_MODEL_OPT_NVFP4_MOE_RECLAIM=1
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
PYTHONHASHSEED=0
```

Prefix caching remains disabled, matching the pinned Station guide.
That setting predates this experimental profile; it is not an optimization introduced by this work.
The profile does not add `--enable-prefix-caching`, does not use MTP speculative decoding, and disables FlashInfer autotuning explicitly.
It also does not use the Gen4B/autotuned result, which measured `44.88197518340701` tokens/s/user but took `2174.438460592006` seconds to start.
The selected reclaimed-v1/offload90 parent configuration measured `41.87059772268699` parser-free AIPerf tokens/s/user and `285.592754706` seconds to API readiness.
The Hermes parser overlay has functional qualification but no separate AIPerf score.

NemoClaw routes the profile through provider `vllm-local`, model `nemotron-ultra`, and effective context length `262144` using the normal inference and Hermes lifecycle.
Generated gateway configuration and the dashboard mirror receive the same route and context; do not edit sandbox configuration files directly.
Nemotron Ultra requires the `qwen3_coder` tool-call parser, not the Hermes tool parser.

This profile has prior benchmark and functional evidence, but it has not completed a fresh physical-DGX-Station qualification from the current PR.

<Warning>
DGX Station and its managed-vLLM paths remain Deferred until NemoClaw completes end-to-end validation on physical DGX Station hardware.
</Warning>

## Run Non-Interactive Onboarding

Use an already-running server.

```bash
NEMOCLAW_PROVIDER=vllm \
  $$nemoclaw onboard --non-interactive
```

Install or start managed vLLM on a supported host.

```bash
NEMOCLAW_PROVIDER=install-vllm \
  $$nemoclaw onboard --non-interactive
```

On DGX Spark and DGX Station, `NEMOCLAW_PROVIDER=install-vllm` is sufficient for a non-interactive run.
Add `NEMOCLAW_EXPERIMENTAL=1` on a generic Linux NVIDIA GPU host.
Non-interactive runs use the profile default unless you set `NEMOCLAW_VLLM_MODEL`.
On DGX Station, a direct provider-only run therefore selects `deepseek-v4-flash`; the installer express flow sets the Nemotron 3 Ultra override for you.

## Select a Managed Model

Set `NEMOCLAW_VLLM_MODEL=<slug>` before onboarding to select a model without prompting.
NemoClaw applies the registered `vllm serve` arguments, including the reasoning parser, tool-call parser, and `--max-model-len`.

| Slug | Hugging Face model | Notes |
|---|---|---|
| `qwen3.6-27b` | `Qwen/Qwen3.6-27B-FP8` | Supported override. |
| `qwen3.6-35b-a3b-nvfp4` | `nvidia/Qwen3.6-35B-A3B-NVFP4` | DGX Spark default. |
| `nemotron-3-nano-4b` | `nvidia/NVIDIA-Nemotron-3-Nano-4B-FP8` | Generic Linux NVIDIA GPU default. |
| `deepseek-v4-flash` | `deepseek-ai/DeepSeek-V4-Flash` | DGX Station profile default outside express install. |
| `nemotron-3-ultra-550b-a55b` | `nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-NVFP4` | DGX Station express-install selection with a pinned model revision and model-specific vLLM image. |
| `deepseek-r1-distill-70b` | `deepseek-ai/DeepSeek-R1-Distill-Llama-70B` | Gated and requires license acceptance. |

Slugs are case-insensitive, and NemoClaw also accepts the full Hugging Face model ID.
An unrecognized value fails before image or model downloads and prints the valid slugs.

Gated models require a Hugging Face token.
Export `HF_TOKEN` before onboarding so NemoClaw can forward it temporarily to the one-shot model downloader.
The token is not retained in the long-lived managed vLLM container after the explicit download completes.

```bash
export HF_TOKEN="<your-hf-token>"
NEMOCLAW_PROVIDER=install-vllm \
  NEMOCLAW_VLLM_MODEL=deepseek-r1-distill-70b \
  $$nemoclaw onboard --non-interactive
```

NemoClaw also accepts `HUGGING_FACE_HUB_TOKEN`.
The host checks the token before `docker pull`, so a missing or empty token stops onboarding before bandwidth is spent on a request that would return `401`.

## Add Managed Serve Arguments

Set `NEMOCLAW_VLLM_EXTRA_ARGS_JSON` to a JSON array of individual non-blank `vllm serve` tokens for operator-owned options that are not in the registry.
NemoClaw trims and validates the array before downloads, shell-quotes each token, and appends the tokens after the registry defaults.

```bash
NEMOCLAW_PROVIDER=install-vllm \
  NEMOCLAW_VLLM_EXTRA_ARGS_JSON='["--max-num-seqs","2","--disable-log-requests"]' \
  $$nemoclaw onboard --non-interactive
```

If the selected image does not support an argument, the managed container exits and NemoClaw prints the log tail.
