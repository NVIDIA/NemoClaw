Hermes Provider routes Hermes Agent through a sandbox-attached OpenShell provider registered during Hermes onboarding.
This option is available only for Hermes Agent.

## Credential Boundary

NemoClaw binds the native provider to the endpoint returned by Hermes authentication.
The agent calls that endpoint while OpenShell retains and injects its credential.
The sandbox does not receive raw provider credentials.

When recovery or a model change finds a previously recorded Hermes endpoint, NemoClaw registers an attached provider for that exact destination.
Public destinations retain validated public IP addresses; the reserved `host.openshell.internal` alias uses the runtime-owned host address.
HTTP endpoints retain HTTP, and the provider allows only model discovery and Chat Completions beneath the recorded path.
A private destination, protected host port, or conflicting provider identity stops recovery before credentials are registered.
Authentication-returned replacement endpoints still require HTTPS.
If no owned native credential remains, resume onboarding and authenticate again before retrying the model change.

The onboarding wizard selects the managed Hermes endpoint.
To configure a new custom endpoint, use [OpenAI-Compatible Endpoint](../custom-endpoints/set-up-openai-compatible-endpoint).

## Model Choices

The Hermes Provider catalog includes curated models such as these examples.

- `moonshotai/kimi-k2.6`.
- `openai/gpt-5.4-mini`.
- `z-ai/glm-5.1`.

The Hermes Provider catalog is separate from the featured catalog shared by NVIDIA Endpoints and OpenRouter.
Catalog updates affect new onboarding choices and do not rewrite existing sandbox configurations.

## Onboard

Run the Hermes onboarding wizard and select **Hermes Provider**.

```bash
nemohermes onboard
```

Select a model when the wizard prompts you.
NemoClaw validates the selected provider and model before creating the sandbox.

## Validation

The wizard validates the selected provider and model before sandbox creation.
