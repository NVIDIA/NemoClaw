OpenClaw documents the sub-agent behavior, `sessions_spawn` tool, `agents.list` configuration, tool policy, nesting, and auth model in [Sub-Agents](https://docs.openclaw.ai/tools/subagents).
Use that page as the source of truth for how OpenClaw sub-agents work.

This page covers the sandbox-specific pieces of a sub-agent setup.
It explains where the OpenClaw config lives, where to put per-agent credentials, and which writable workspace path agents should use.
It also provides a self-contained Omni vision sub-agent example.

## NemoClaw Sandbox Paths

NemoClaw runs OpenClaw inside an OpenShell sandbox.
Use these paths inside the sandbox when you adapt an OpenClaw sub-agent setup:

| Path | Purpose |
|---|---|
| `/sandbox/.openclaw/openclaw.json` | OpenClaw config, including `models.providers`, `agents.defaults`, and `agents.list`. |
| `/sandbox/.openclaw/.config-hash` | Hash for `openclaw.json`. Keep it in sync after manual config edits so OpenClaw can detect the updated config. From the default mutable posture, the next `shields up` synthesizes a missing hash from `openclaw.json`. |
| `/sandbox/.openclaw/agents/<agent-id>/agent/auth-profiles.json` | Per-agent provider credentials. Use this when a sub-agent calls an auxiliary provider directly. |
| `/sandbox/.openclaw/workspace/` | Writable shared workspace path for files the primary agent passes to the sub-agent. |
| `/tmp/gateway.log` | OpenClaw gateway log. Use it to confirm config reloads and diagnose sub-agent failures. |

For file-based tasks, instruct agents to use `/sandbox/.openclaw/workspace/`.
Avoid relying on legacy `.openclaw-data` paths or read-only OpenClaw paths in delegation instructions.

## Omni Vision Sub-Agent Example

This example applies the OpenClaw sub-agent pattern to a vision task.
It keeps the primary `main` agent on the normal NemoClaw inference route.
It adds a `vision-operator` sub-agent backed by an Omni vision model.

| OpenClaw field | Omni example value |
|---|---|
| Primary agent | `main` |
| Primary model | `inference/nvidia/nemotron-3-super-120b-a12b` |
| Auxiliary provider | `nvidia-omni` |
| Sub-agent | `vision-operator` |
| Sub-agent model | `nvidia-omni/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning` |
| Delegation tool | `sessions_spawn` |

The sub-agent uses Omni as the specialist model for image tasks.
The primary orchestration model remains responsible for conversation, planning, and deciding when to delegate.

## Update the Sandbox Config

<Note>
Finish the [Quickstart](../get-started/quickstart) and start the target sandbox before you run the `docker exec` commands in this section.
These commands run on the host that owns the sandbox containers and discover the running sandbox container from the `openshell.ai/sandbox-name` Docker label.
If you have not created a sandbox yet, onboard one first, such as `my-assistant`.
</Note>

Fetch the current OpenClaw config from the sandbox.
Patch it with your auxiliary provider and `agents.list` changes, then upload it.
Run the following commands from the host that owns the sandbox containers when you use Docker-driver sandboxes.

### Export the Current Config

The container name includes a runtime suffix, so discover it from the OpenShell sandbox label:

```bash
export SANDBOX=my-assistant
export SANDBOX_CTR=$(docker ps --filter "label=openshell.ai/sandbox-name=$SANDBOX" --format "{{.Names}}" | sed -n '1p')
if [ -z "$SANDBOX_CTR" ]; then
  echo "No running sandbox container found for $SANDBOX. Start the sandbox before editing its config."
  exit 1
fi
OPENCLAW_CONFIG_FILE=$(mktemp "${TMPDIR:-/tmp}/openclaw.config.XXXXXX")
export OPENCLAW_CONFIG_FILE
chmod 600 "$OPENCLAW_CONFIG_FILE"
docker exec --user root "$SANDBOX_CTR" cat /sandbox/.openclaw/openclaw.json > "$OPENCLAW_CONFIG_FILE"
```

If `SANDBOX_CTR` is empty, the sandbox is not running on this host.
Start the sandbox, confirm that `docker ps` shows the matching `openshell.ai/sandbox-name` label, then rerun the export commands before continuing.
`mktemp` creates a unique host-user-only file and assigns its path to `OPENCLAW_CONFIG_FILE`.

<Warning>
This direct-provider example copies the NVIDIA API key into two sandbox files.
The uploaded `openclaw.json` has mode `0444`, so every process in the sandbox can read the key.
The sub-agent auth profile has mode `0600`, so the sandbox user and root can read it.
Both copies remain after gateway restarts and sandbox stop-and-start cycles until you replace or remove them, or destroy the sandbox.
Use a dedicated, narrowly scoped key, and follow [Remove or Rotate the Credential](#remove-or-rotate-the-credential) when you finish.
Destroying the sandbox removes the credential copies, but it also removes all persistent data in that sandbox.
</Warning>

### Prepare the Updated Config

Create another unique host-user-only file with the current hosted Omni model and the `vision-operator` entry.
This command reads the API key without echoing it and keeps the value out of the child process's operating-system argument list.

```bash
OPENCLAW_UPDATED_FILE=$(mktemp "${TMPDIR:-/tmp}/openclaw.updated.XXXXXX")
export OPENCLAW_UPDATED_FILE
chmod 600 "$OPENCLAW_UPDATED_FILE"
(
  read -rsp "NVIDIA API key: " NVIDIA_API_KEY
  printf '\n'
  export NVIDIA_API_KEY
  python3 -c '
import json
import os
import sys

model_id = "nvidia/nemotron-3-nano-omni-30b-a3b-reasoning"
provider_id = "nvidia-omni"
model_ref = f"{provider_id}/{model_id}"
config = json.load(sys.stdin)

config["models"]["providers"][provider_id] = {
    "baseUrl": "https://integrate.api.nvidia.com/v1",
    "apiKey": os.environ["NVIDIA_API_KEY"],
    "api": "openai-completions",
    "models": [
        {
            "id": model_id,
            "name": model_ref,
            "reasoning": True,
            "input": ["text", "image"],
            "cost": {
                "input": 0,
                "output": 0,
                "cacheRead": 0,
                "cacheWrite": 0,
            },
            "contextWindow": 131072,
            "maxTokens": 16384,
        }
    ],
}
config["agents"]["defaults"]["subagents"] = {
    "maxConcurrent": 4,
    "maxSpawnDepth": 1,
}
config["agents"]["defaults"]["timeoutSeconds"] = 300
agents_by_id = {
    agent["id"]: agent for agent in config["agents"].get("list", [])
}
main_agent = agents_by_id.setdefault(
    "main",
    {
        "id": "main",
        "model": {
            "primary": "inference/nvidia/nemotron-3-super-120b-a12b",
        },
        "tools": {"profile": "full"},
    },
)
allowed_agents = main_agent.setdefault("subagents", {}).setdefault("allowAgents", [])
if "vision-operator" not in allowed_agents:
    allowed_agents.append("vision-operator")
agents_by_id["vision-operator"] = {
    "id": "vision-operator",
    "model": {"primary": model_ref},
    "tools": {
        "profile": "full",
        "deny": ["message", "sessions_spawn"],
    },
}
config["agents"]["list"] = list(agents_by_id.values())

json.dump(config, sys.stdout, indent=2)
' < "$OPENCLAW_CONFIG_FILE" > "$OPENCLAW_UPDATED_FILE"
)
```

The updated config contains the NVIDIA API key until you delete the file.
Do not commit it.

Verify both model references before you upload the config:

```bash
python3 -c '
import json
import sys

with open(sys.argv[1], encoding="utf-8") as config_file:
    config = json.load(config_file)

provider = config["models"]["providers"]["nvidia-omni"]
vision_operator = next(
    agent for agent in config["agents"]["list"] if agent["id"] == "vision-operator"
)
print(provider["models"][0]["id"])
print(vision_operator["model"]["primary"])
' "$OPENCLAW_UPDATED_FILE"
```

Expected output:

```text
nvidia/nemotron-3-nano-omni-30b-a3b-reasoning
nvidia-omni/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning
```

For a sub-agent other than the Omni example, copy the exported config to the updated config file.
Use `cp "$OPENCLAW_CONFIG_FILE" "$OPENCLAW_UPDATED_FILE"`.
Before uploading the file, add your provider under `models.providers` and your sub-agent under `agents.list`.
Do not commit any file that contains a real API key.

### Upload the Updated Config

Upload the patched config and refresh the hash.
In the default mutable state, this keeps the local hash consistent but does not make it tamper-proof.
Use NemoClaw runtime controls when the sandbox needs a hardened config posture after the manual edit.
From the default mutable posture, `shields up` regenerates a stale hash and synthesizes a missing hash.
Keep the refresh step so OpenClaw detects the update immediately.

```bash
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/.config-hash
docker exec --user root -i "$SANDBOX_CTR" sh -c 'cat > /sandbox/.openclaw/openclaw.json' < "$OPENCLAW_UPDATED_FILE"
docker exec --user root "$SANDBOX_CTR" /bin/bash -c "cd /sandbox/.openclaw && sha256sum openclaw.json > .config-hash"
docker exec --user root "$SANDBOX_CTR" chown sandbox:sandbox /sandbox/.openclaw/openclaw.json /sandbox/.openclaw/.config-hash
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/.config-hash
```

After uploading the config, check `/tmp/gateway.log`.
Confirm that the gateway hot-reloaded the provider or `agents.list` change:

```bash
nemoclaw "$SANDBOX" logs --since 5m --tail 200
nemoclaw "$SANDBOX" agents list --json
```

Expected output:

```text
config change detected; evaluating reload (...)
config hot reload applied (...)
```

The `agents list` output should include `vision-operator`.

## Add Sub-Agent Credentials

Put the provider key in the sub-agent auth profile when the auxiliary model uses a provider outside the normal NemoClaw inference route.
For the Omni example:

```text
/sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json
```

Use the same provider ID that appears in `models.providers`, such as `nvidia-omni`.
Create another unique host-user-only file:

```bash
AUTH_PROFILES_FILE=$(mktemp "${TMPDIR:-/tmp}/auth-profiles.XXXXXX")
export AUTH_PROFILES_FILE
chmod 600 "$AUTH_PROFILES_FILE"
(
  read -rsp "NVIDIA API key: " NVIDIA_API_KEY
  printf '\n'
  export NVIDIA_API_KEY
  python3 -c '
import json
import os
import sys

json.dump(
    {
        "providers": {
            "nvidia-omni": {
                "apiKey": os.environ["NVIDIA_API_KEY"],
            }
        }
    },
    sys.stdout,
    indent=2,
)
' > "$AUTH_PROFILES_FILE"
)
```

The file contains the NVIDIA API key until you delete it.
Upload the file into the sandbox:

```bash
docker exec --user root "$SANDBOX_CTR" mkdir -p /sandbox/.openclaw/agents/vision-operator/agent
docker exec --user root -i "$SANDBOX_CTR" sh -c 'cat > /sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json' < "$AUTH_PROFILES_FILE"
docker exec --user root "$SANDBOX_CTR" chmod 600 /sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json
```

After uploading the auth profile, make sure the sandbox user owns the sub-agent directory:

```bash
docker exec --user root "$SANDBOX_CTR" chown -R sandbox:sandbox /sandbox/.openclaw/agents/vision-operator
```

The sandbox copies remain credential-bearing state after you delete the host files.

## Allow Auxiliary Provider Egress

Update the OpenShell network policy for the binary that makes the request when the sub-agent calls a provider directly.
In this example, the OpenClaw gateway runs as `/usr/local/bin/node`.
The NVIDIA endpoint policy must allow that binary.

Refer to [Customize the Network Policy](../network-policy/customize-network-policy) for policy update workflows.

## Sub-Agent Gateway Connectivity

Spawned sub-agents connect back to the OpenClaw gateway over WebSocket at `OPENCLAW_GATEWAY_URL`.
Inside the sandbox, this connection runs through the enforced process tree.
The OpenShell proxy always blocks loopback destinations in that process tree.
NemoClaw points `OPENCLAW_GATEWAY_URL` at the sandbox's own interface address, such as `ws://10.200.0.2:18790`.
The base sandbox policy allowlists that endpoint through `openclaw_gateway_dialback`.

### Troubleshoot Dial-Back Failures

The dial-back path is blocked if `sessions_spawn` returns `gateway closed (1006 abnormal closure (no close frame))` and the gateway log shows no connection attempt.
Check the following:

1. `OPENCLAW_GATEWAY_URL` in the gateway process environment targets the sandbox interface address, not `127.0.0.1`.
2. The active policy allows that address and port. Custom `NEMOCLAW_DASHBOARD_PORT` or proxy subnet values need a matching `openshell policy update`.
3. Do not point the dial-back at `127.0.0.1`; the proxy denies loopback regardless of policy.

## Add Delegation Instructions

OpenClaw handles `sessions_spawn`.
The primary agent still needs task instructions.
Place those instructions in the writable workspace, for example:

```text
/sandbox/.openclaw/workspace/TOOLS.md
```

Tell `main` to delegate image tasks to `vision-operator`.
Tell the sub-agent to read the image path it receives.
Adapt that file for other task-specific models.

## Remove or Rotate the Credential

These procedures reuse the shell variables and temporary files from the earlier configuration update.
For rotation in a new shell or after host cleanup, rerun [Export the Current Config](#export-the-current-config) before you prepare the replacement configuration.
For removal, restore `OPENCLAW_CONFIG_FILE` only when it still identifies the export captured before you added the direct provider.
In a new shell, rerun only the container-discovery commands from that section, and use the manual-removal fallback below.
Do not restore a new export as though it were the pre-change configuration.

To rotate the key, repeat [Prepare the Updated Config](#prepare-the-updated-config) and [Add Sub-Agent Credentials](#add-sub-agent-credentials) with the replacement key.
Upload both files before you revoke the old key.

To remove the direct provider without destroying the sandbox, restore the original config that remains in `OPENCLAW_CONFIG_FILE`, remove the sub-agent auth profile, and refresh the config hash:

```bash
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/.config-hash
docker exec --user root -i "$SANDBOX_CTR" sh -c 'cat > /sandbox/.openclaw/openclaw.json' < "$OPENCLAW_CONFIG_FILE"
docker exec --user root "$SANDBOX_CTR" /bin/bash -c "cd /sandbox/.openclaw && sha256sum openclaw.json > .config-hash"
docker exec --user root "$SANDBOX_CTR" rm -f /sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json
docker exec --user root "$SANDBOX_CTR" chown sandbox:sandbox /sandbox/.openclaw/openclaw.json /sandbox/.openclaw/.config-hash
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/.config-hash
```

This restores the config captured before this procedure.
Do not use that file after other config changes, because restoring it would discard those changes.

### Manually Remove the Direct Provider

If the original file is unavailable or no longer current, revoke the provider key before you edit the live config.
Rerun the container-discovery commands from [Export the Current Config](#export-the-current-config), but do not restore a stale export.
Instead, export the current config to new host-user-only files and remove only the Omni provider, the `vision-operator` agent, and that agent's entry in `main.subagents.allowAgents`:

```bash
OPENCLAW_CURRENT_FILE=$(mktemp "${TMPDIR:-/tmp}/openclaw.current.XXXXXX")
OPENCLAW_CLEANED_FILE=$(mktemp "${TMPDIR:-/tmp}/openclaw.cleaned.XXXXXX")
chmod 600 "$OPENCLAW_CURRENT_FILE" "$OPENCLAW_CLEANED_FILE"
docker exec --user root "$SANDBOX_CTR" cat /sandbox/.openclaw/openclaw.json > "$OPENCLAW_CURRENT_FILE"
python3 -c '
import json
import sys

provider_id = "nvidia-omni"
agent_id = "vision-operator"
config = json.load(sys.stdin)

providers = config.get("models", {}).get("providers", {})
providers.pop(provider_id, None)

agents = config.get("agents", {})
agent_list = agents.get("list", [])
retained_agents = []
for agent in agent_list:
    if not isinstance(agent, dict):
        retained_agents.append(agent)
        continue
    if agent.get("id") == agent_id:
        continue
    if agent.get("id") == "main":
        subagents = agent.get("subagents")
        if isinstance(subagents, dict):
            allowed_agents = subagents.get("allowAgents")
            if isinstance(allowed_agents, list):
                subagents["allowAgents"] = [
                    allowed_agent
                    for allowed_agent in allowed_agents
                    if allowed_agent != agent_id
                ]
                if not subagents["allowAgents"]:
                    subagents.pop("allowAgents")
                if not subagents:
                    agent.pop("subagents")
    retained_agents.append(agent)
agents["list"] = retained_agents

json.dump(config, sys.stdout, indent=2)
' < "$OPENCLAW_CURRENT_FILE" > "$OPENCLAW_CLEANED_FILE"
```

Upload the cleaned config, remove the sub-agent auth profile, and refresh the config hash:

```bash
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 644 /sandbox/.openclaw/.config-hash
docker exec --user root -i "$SANDBOX_CTR" sh -c 'cat > /sandbox/.openclaw/openclaw.json' < "$OPENCLAW_CLEANED_FILE"
docker exec --user root "$SANDBOX_CTR" /bin/bash -c "cd /sandbox/.openclaw && sha256sum openclaw.json > .config-hash"
docker exec --user root "$SANDBOX_CTR" rm -f /sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json
docker exec --user root "$SANDBOX_CTR" chown sandbox:sandbox /sandbox/.openclaw/openclaw.json /sandbox/.openclaw/.config-hash
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/openclaw.json
docker exec --user root "$SANDBOX_CTR" chmod 444 /sandbox/.openclaw/.config-hash
```

Verify the live config and auth-profile path before you delete the host temporary files.
Both commands must print a verification message.
If either command exits with an error, keep the host files and correct the remaining state before you continue.

```bash
if docker exec --user root "$SANDBOX_CTR" cat /sandbox/.openclaw/openclaw.json | python3 -c '
import json
import sys

provider_id = "nvidia-omni"
agent_id = "vision-operator"
config = json.load(sys.stdin)
providers = config.get("models", {}).get("providers", {})
agents = config.get("agents", {}).get("list", [])

provider_remains = provider_id in providers
agent_remains = any(
    isinstance(agent, dict) and agent.get("id") == agent_id
    for agent in agents
)
allow_list_remains = any(
    isinstance(agent, dict)
    and agent.get("id") == "main"
    and agent_id in agent.get("subagents", {}).get("allowAgents", [])
    for agent in agents
)
if provider_remains or agent_remains or allow_list_remains:
    raise SystemExit(1)
'; then
  echo "Provider, agent, and allow-list cleanup verified."
else
  echo "Direct provider or sub-agent state remains in openclaw.json." >&2
  exit 1
fi

if docker exec --user root "$SANDBOX_CTR" test ! -e /sandbox/.openclaw/agents/vision-operator/agent/auth-profiles.json; then
  echo "Sub-agent auth-profile removal verified."
else
  echo "The sub-agent auth profile still exists." >&2
  exit 1
fi

nemoclaw "$SANDBOX" agents list --json
rm -f "$OPENCLAW_CURRENT_FILE" "$OPENCLAW_CLEANED_FILE"
```

The final agent listing must not include `vision-operator`.

Delete the host temporary files after the upload, verification, and any rollback window:

```bash
rm -f "$OPENCLAW_CONFIG_FILE" "$OPENCLAW_UPDATED_FILE" "$AUTH_PROFILES_FILE"
```
