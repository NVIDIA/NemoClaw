Use the custom Anthropic-compatible provider to configure a custom base URL and model with `COMPATIBLE_ANTHROPIC_API_KEY`.
The runtime API differs by agent capability.

## Run Onboarding

Start the onboard wizard.

```bash
$$nemoclaw onboard
```

Select **Other Anthropic-compatible endpoint**.
Enter the endpoint base URL, model ID, and API key when prompted.
Use any non-empty placeholder such as `dummy` when the endpoint does not require authentication.
For a direct custom endpoint, OpenShell holds the upstream credential and the sandbox receives a scoped `openshell:resolve:env:...` reference instead of the raw key.
For AWS Bedrock Runtime, a host-local adapter holds the AWS credentials and OpenShell receives only the adapter token.

## Understand Native Endpoint Selection

New qualifying custom endpoints use a sandbox-attached OpenShell provider.
Use a public endpoint or an explicitly trusted private hostname or IP address.
NemoClaw rejects an unverified Anthropic-compatible route that uses `host.openshell.internal` because the alias does not prove which process owns the selected port.
Follow the [custom endpoint security requirements](custom-endpoint-security) for private destinations and address pinning.

The native route binds the endpoint, API, and credential source to the selected sandbox.
OpenShell supplies the host credential at egress; the agent receives a credential reference.
Existing sandboxes without a native attachment retain their recorded shared route on OpenShell `0.0.x`.
For retained shared selections, follow the [resume and rebuild restrictions](../../manage-sandboxes/operate-sandboxes/recover-and-rebuild-sandboxes#resolve-rebuild-preflight-stops).
OpenShell `0.1.3` removes `inference.local`; this repair does not complete migration of every shared route.
Native local qualification remains pending for this upgrade.

## Understand OpenClaw Validation

OpenClaw uses the native Anthropic Messages frontend for this provider.
NemoClaw validates the endpoint with a non-streaming `/v1/messages` request and then a `stream: true` request to the same path.

The streaming check requires exactly one `message_start`, at least one `content_block_delta`, and one `message_stop` in a well-formed server-sent event sequence.
It also forces the endpoint to call the `emit_ok` validation tool.
The stream must contain a native `tool_use` content block named `emit_ok` and finish the request with `stop_reason: tool_use`.
JSON-shaped assistant text does not satisfy either requirement, even when it names `emit_ok` and contains valid JSON.
NemoClaw reports `anthropic-streaming-missing-tool-use` when the native block is absent and `anthropic-streaming-missing-tool-use-stop-reason` when the matching stop reason is absent.
An endpoint whose non-streaming response works but whose streaming response is malformed fails during onboarding.

Set `NEMOCLAW_REASONING=true` to skip both the streaming sequence and forced tool-call checks for a reasoning-only model.
Agent runs still use streaming and native tool calls, so this setting moves either defect to runtime.

Refer to [Onboarding fails with duplicate Anthropic message_start events](../../reference/troubleshooting#onboarding-fails-with-duplicate-anthropic-message_start-events) when the streaming validation fails with duplicate start events.
Refer to [Onboarding rejects an Anthropic-compatible tool call](../../reference/troubleshooting#onboarding-rejects-an-anthropic-compatible-tool-call) when the endpoint returns a tool request as assistant text or omits the tool-use stop reason.

</AgentOnly>

## Understand Hermes Routing

Hermes uses OpenAI Chat Completions for this provider.
For a qualifying native selection, Hermes calls the recorded endpoint through its sandbox-attached OpenShell provider.
NemoClaw validates `/v1/chat/completions` and configures the same API for inference.
The route keeps `COMPATIBLE_ANTHROPIC_API_KEY` as its host credential binding.
Hermes configuration uses `${COMPATIBLE_ANTHROPIC_API_KEY}`; its sandbox environment supplies a scoped OpenShell credential reference instead of the API key.
For Bedrock, the configured endpoint is the host-local adapter URL.
The OpenClaw-only native Anthropic `emit_ok` streaming check does not run on this route.

This path avoids duplicate Anthropic SSE `message_start` events.
If the endpoint only implements Anthropic Messages, onboarding stops instead of creating a Hermes sandbox with an unusable runtime route.
The native Hermes Anthropic-to-OpenAI route still needs live request qualification.

OpenClaw custom Anthropic routes and first-party Anthropic routes remain on the native Anthropic Messages frontend.
AWS Bedrock routes keep their existing OpenAI-compatible adapter behavior.

</AgentOnly>

<AgentOnly variant="deepagents">

## Understand Deep Agents Routing

Deep Agents Code supports only OpenAI-compatible inference for this provider.
NemoClaw validates `/v1/chat/completions` and selects `openai-completions`.
For a qualifying native selection, `/sandbox/.deepagents/config.toml` records the direct endpoint or, for Bedrock, the host-local adapter URL.
The file sets `api_key_env = "COMPATIBLE_ANTHROPIC_API_KEY"`.
The sandbox environment supplies the scoped OpenShell credential reference for that name.
Retained shared selections use `https://inference.local/v1` on OpenShell `0.0.x`.
The OpenClaw-only native Anthropic `emit_ok` streaming check does not run on this route.

If the endpoint implements only Anthropic Messages, onboarding stops instead of creating a Deep Agents sandbox with an unusable runtime route.

</AgentOnly>

## Run Non-Interactive Onboarding

Set `NEMOCLAW_PROVIDER=anthropicCompatible` and provide the endpoint URL, model, and credential.
Replace the example endpoint and model with your server values.
Use `dummy` only when that server does not require authentication.

```bash
NEMOCLAW_PROVIDER=anthropicCompatible \
  NEMOCLAW_ENDPOINT_URL=https://inference.example.com \
  NEMOCLAW_MODEL=my-model \
  COMPATIBLE_ANTHROPIC_API_KEY=dummy \
  $$nemoclaw onboard --non-interactive
```
