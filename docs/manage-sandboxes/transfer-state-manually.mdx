Use manual transfer when you need to inspect or move specific state files.
OpenShell preserves the native home/workspace during routine lifecycle operations, and NemoClaw transfers the complete tree during rebuild. Use manual transfer for an independent backup or a targeted cross-sandbox move.

## Replace a Sandbox

When recovery requires a replacement sandbox, preserve the old sandbox until configuration, transferred state, and required workflows pass verification.
Complete replacement-specific prerequisites, such as selecting an approved [corporate certificate authority (CA) bundle](../../security/configure-corporate-ca-trust), before onboarding.
This procedure copies selected state and recreates configuration through supported controls.
It does not copy credentials or live scheduler stores.

### Record the Required Configuration

<Warning>
Native scheduler listings and run history can contain credential values from existing jobs.
Inspect them in a trusted terminal without recording or sharing the raw output.
</Warning>

Record only non-secret configuration before you start:

- The agent runtime and any explicitly selected serving-catalog profile.
- The inference provider, model, endpoint, and gateway or attachment settings.
- The policy tier, applied presets, and required custom policy rules.
- Model Context Protocol (MCP) registration metadata and messaging channel settings.
- Complete credential-free scheduled-job definitions, required options and files, owning profiles, and original enabled states.

Inspect the old sandbox's settings with these commands:

```bash
$$nemoclaw <old-sandbox> status --json
$$nemoclaw <old-sandbox> inference get
$$nemoclaw <old-sandbox> policy list
$$nemoclaw <old-sandbox> policy get
```

Keep credential values in their approved secret source.
Exclude them from recorded arguments, environment assignments, prompt text, and referenced files.
Preserve only secret references supported by the destination's documented credential mechanism.
Keep the old sandbox's live job definitions and files for rollback.

Status listings can omit task content.
If a required definition is unavailable, recover it through its native owner before changing the old sandbox.

### Create and Verify the Replacement

Choose an unused sandbox name and the recorded agent runtime.
Select the recorded provider, model, endpoint, policy tier, and presets through the supported onboarding prompts.

If the old sandbox used a serving-catalog profile, add `--profile <recorded-profile>` to the following command.
This option does not select a native Hermes profile.
Refer to [Onboard Options](../../reference/commands) for profile compatibility and conflicting inference overrides.
Keep replacement messaging channels and scheduled work inactive during setup.

Start replacement onboarding:

```bash
$$nemoclaw onboard --fresh --name <new-sandbox> --agent <recorded-agent>
```

`--fresh` starts a separate onboarding session instead of resuming interrupted onboarding.

Inspect the replacement before transferring state:

```bash
$$nemoclaw <new-sandbox> status --json
$$nemoclaw <new-sandbox> inference get
$$nemoclaw <new-sandbox> policy list
$$nemoclaw <new-sandbox> policy get
```

Compare its agent, provider, model, serving-profile provenance, inference route, and effective policy with the recorded requirements.
Follow [Customize the Network Policy](../../network-policy/customize-network-policy) to restore required custom rules.
Then verify the effective policy again.
Stop if a required choice cannot be reproduced or verified, or if status reports drift.
Keep the old sandbox and resolve the mismatch before transferring state.

### Stop Writers Before Transferring State

Pause the work that writes mutable state before copying it.
NemoClaw has no generic scheduler controls or scheduled-task migration command.

Use the applicable native controls to stop future dispatch:

<AgentOnly variant="openclaw">
From the host, list all jobs and disable each enabled job that you intend to move:

```bash
$$nemoclaw <old-sandbox> exec -- openclaw cron list --all --json
$$nemoclaw <old-sandbox> exec -- openclaw cron disable <old-job-id>
$$nemoclaw <old-sandbox> exec -- openclaw cron list --all --json
$$nemoclaw <old-sandbox> exec -- openclaw cron runs <old-job-id>
```

Confirm that each selected job has `enabled: false` and is no longer `running`.
</AgentOnly>

<AgentOnly variant="hermes">
From the host, list all jobs and pause each enabled job that you intend to move:

```bash
$$nemoclaw <old-sandbox> exec -- hermes --profile default cron list --all
$$nemoclaw <old-sandbox> exec -- hermes --profile default cron pause <old-job-id>
$$nemoclaw <old-sandbox> exec -- hermes --profile default cron list --all
$$nemoclaw <old-sandbox> exec -- hermes --profile default cron runs <old-job-id>
```

Repeat for every named profile that owns scheduled work, replacing `default` with its profile name.
Confirm that each selected job is marked `[paused]` or `[disabled]`.
</AgentOnly>

<AgentOnly variant="deepagents">
NemoClaw provides no managed scheduler controls for Deep Agents Code.
Use the native interface of any scheduler you configured for `dcode` runs.
</AgentOnly>

For externally scheduled work on any agent, disable dispatch through the owning service's native interface.
Do not treat a successful pause or disable command as proof that in-flight work has finished.
Inspect the owning scheduler's run history and the old sandbox's application state.
Wait for active work to finish before copying mutable state.

<AgentOnly variant="openclaw,hermes">
Pause old messaging channels through [Pause and Resume a Channel](../messaging-channels/manage-messaging-channels#pause-and-resume-a-channel), including any requested rebuild.
Stopping the sandbox alone does not clear enabled channels from the messaging plan's conflict checks.
</AgentOnly>

Pause any other integration that writes the selected state through its owning interface.
If you cannot confirm that dispatch and active work have stopped, stop the transfer and cutover.
Keep the old sandbox and resolve the condition through the work's owning interface.

### Transfer Reviewed State and Restore Credentials

Select the workspace files, agent state, scripts, skills, and working directories required by the recorded jobs.
Review those files and job definitions for credentials before any download or upload.
Exclude raw credential values from every transfer copy and recorded job definition.
Do not copy live cron stores, credential stores, machine-local identities, or the old agent configuration wholesale.
Exclude messaging-session and pairing state, including custom session paths and copies under named profiles, from replacement and rollback transfers.

<AgentOnly variant="hermes">
Do not transfer `/sandbox/.hermes/platforms/` or legacy `dashboard-home` messaging sessions into the replacement.
These paths can contain credentials such as WhatsApp `session/creds.json`.
</AgentOnly>

<AgentOnly variant="openclaw">
Do not transfer native WhatsApp session state or credential and account directories outside the reviewed workspace files.
These include `/sandbox/.openclaw/whatsapp/`, `/sandbox/.openclaw/credentials/`, `/sandbox/.openclaw/wechat/`, and `/sandbox/.openclaw/openclaw-weixin/`.
</AgentOnly>

Follow [Download State](#download-state) and [Upload State](#upload-state), including their per-agent exclusions.
Verify that the required files are present in the replacement before recreating jobs.

Provision managed inference and MCP credentials through their documented [provider bindings](../../security/credential-storage).
For other job credentials, use the job runner's documented secret mechanism and credential input.
Do not pass credential values in job-creation arguments, environment assignments, or prompt text through host-shell `exec` commands.
If no supported credential mechanism can preserve the job's authentication, stop the migration and retain the old sandbox.

<AgentOnly variant="openclaw">
Recreate each job with `$$nemoclaw <new-sandbox> exec -- openclaw cron add --disabled` and its credential-free recorded options.
List all replacement jobs and confirm `enabled: false` before continuing.
</AgentOnly>

<AgentOnly variant="hermes">
Recreate each job with `$$nemoclaw <new-sandbox> exec -- hermes --profile <profile> cron create --paused` and its credential-free recorded options.
Use the corresponding profile for each job.
List all replacement jobs in every profile and confirm `[paused]` or `[disabled]` before continuing.
</AgentOnly>

If the old sandbox has managed MCP servers, retrieve each required credential from an approved secret manager or masked prompt.
In the host shell, export its value under the original credential environment-variable name immediately before `mcp add`.
Then [add the MCP server](../mcp-servers/add-an-mcp-server) to the new sandbox.
Use the original URL, credential environment-variable name, denied-tool selectors, and trusted-private declaration.

Unset the host variable after the command, including when the command fails.
Unsetting it clears that shell's value; OpenShell retains the credential in its provider store for the registered server.
Repeat for each required server without placing credential values in shell history or copied configuration.

Verify credential resolution and tool discovery for each server:

```bash
$$nemoclaw <new-sandbox> mcp status <server> --json
$$nemoclaw <new-sandbox> mcp status <server> --tools
```

Confirm that `provider.credentialResolution.ok` is `true` and tool discovery succeeds.
If no MCP server is configured, verify the affected feature through its normal HTTPS workflow instead.
Keep HTTPS and certificate validation enabled.

### Verify Integrations Before Enabling Schedules

Confirm that the old sandbox's scheduled work and integrations remain inactive.

<AgentOnly variant="openclaw,hermes">
Restore the recorded messaging channel settings through [Add Channels After Onboarding](../messaging-channels/add-channels-after-onboarding).
Complete its required rebuild while replacement jobs remain disabled or paused.

Removing a WhatsApp Linked Device entry invalidates that sandbox's session.
Rollback after removing the old entry requires fresh pairing on the old sandbox.

For WhatsApp, remove the old sandbox's entry from the phone's Linked Devices before pairing the replacement.
Follow the [channel removal guidance](../messaging-channels/manage-messaging-channels#remove-a-channel) for this external step.
Pair the replacement through [Set Up WhatsApp](../messaging-channels/set-up-whatsapp).

For other channels, pair or provision credentials through their supported setup flow.
Do not restore native messaging-session files into the replacement.
</AgentOnly>

Restore other required integration settings through their supported configuration controls.
Enable the replacement's required integrations through their supported controls, including messaging channels where configured.
Verify their normal workflows while replacement jobs remain disabled or paused.
For example, verify the messaging channel before enabling a job that sends messages through it.
If any required integration fails verification, keep schedules inactive and follow [Roll Back or Clean Up](#roll-back-or-clean-up).

Reconcile missed runs and expired one-shot jobs through the native scheduler before enabling replacement jobs.
Keep each job disabled until its required credential access and integrations are verified.
Enable only the jobs recorded as enabled before the move:

<AgentOnly variant="openclaw">
Use `$$nemoclaw <new-sandbox> exec -- openclaw cron enable <new-job-id>`.
Use `cron list --all --json` through the same `exec` command to verify the new job's state.
</AgentOnly>

<AgentOnly variant="hermes">
Use `$$nemoclaw <new-sandbox> exec -- hermes --profile <profile> cron resume <new-job-id>`.
Use `cron list --all` through the same profile's `exec` command to verify the new job's state.
</AgentOnly>

For external schedules, set and verify the new target while dispatch remains disabled.
Re-enable dispatch only after its required integrations pass verification.
Verify intended execution while the old jobs remain inactive.
Move clients to the replacement only after its required workflows pass verification.

### Roll Back or Clean Up

If verification fails, inspect the reported endpoint, policy, or integration condition before retrying.
Keep the old sandbox as the rollback target.
Disable or pause replacement jobs with their native controls and job IDs.
Disable external dispatch through its owning service.
Wait for replacement work to finish, then pause replacement integrations through their supported controls.
Confirm that replacement dispatch and integrations are inactive.

Recover any required reviewed state while both sandboxes' writers remain inactive.

<AgentOnly variant="openclaw,hermes">
If the replacement was paired with WhatsApp, remove its entry from the phone's Linked Devices before pairing the old sandbox.
</AgentOnly>

If a channel session was invalidated during cutover, repeat its supported pairing or credential setup on the old sandbox.
Restore and verify the old sandbox's required integrations before resuming its scheduled work.
Verify delivery before resuming jobs that depend on that channel.
Then enable or resume only the originally enabled jobs, using their original job IDs, and verify their state.
For external schedules, restore and verify the old target while dispatch remains disabled, then re-enable it.

<Warning>
Destroy removes the named sandbox's native state.
Copy any files you need before either cleanup command below.
</Warning>

After successful verification and client cutover, destroy the old sandbox by its original name:

```bash
$$nemoclaw <old-sandbox> destroy
$$nemoclaw list
```

If you abandon the replacement, recover any files you need from it, then destroy only the new sandbox:

```bash
$$nemoclaw <new-sandbox> destroy
$$nemoclaw list
```

For either cleanup, confirm that destroy reports the named sandbox destroyed and that the name no longer appears in the list.
If destroy fails or reports residual cleanup, resolve the reported condition before retrying.

Destroy preserves workspace-level MCP providers.
Inspect its printed provider names, and resolve any provider-inventory warning before selecting a provider for cleanup.
Remove a retained provider only after confirming that no remaining sandbox uses it, following [MCP Credential Cleanup](../mcp-servers/manage-mcp-servers#rotate-a-credential).

## Download State

Use `$$nemoclaw <name> download` to copy files from the sandbox to your host.
The wrapper rejects a directory that contains a symbolic link or another special file before it invokes the OpenShell download or creates the host destination.

<AgentOnly variant="openclaw">

```bash
SANDBOX=my-assistant
BACKUP_DIR=~/.nemoclaw/backups/$(date +%Y%m%d-%H%M%S)
mkdir -p "$BACKUP_DIR"

$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/SOUL.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/USER.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/IDENTITY.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/AGENTS.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/TOOLS.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/HEARTBEAT.md "$BACKUP_DIR/"
```

OpenClaw creates `MEMORY.md` and `memory/` only after it stores memory.
Run each applicable command only when that sandbox path exists:

```bash
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/MEMORY.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.openclaw/workspace/memory/ "$BACKUP_DIR/memory/"
```

The same directory also holds `POLICY.md`. NemoClaw writes that file during the onboarding policy step and refreshes it when you add or remove a network-policy preset.
Download it for reference only, and do not upload a saved copy. See [Explain Network Policy to Agents](../../network-policy/explain-network-policy-to-agents).

</AgentOnly>
<AgentOnly variant="hermes">

For Hermes, prefer [Persist Sandbox State](create-and-restore-snapshots) for normal lifecycle preservation of `state.db`.
Use manual download and upload only when you need to inspect or transfer a specific file.

```bash
SANDBOX=my-hermes
BACKUP_DIR=~/.nemoclaw/backups/$(date +%Y%m%d-%H%M%S)
mkdir -p "$BACKUP_DIR"

$$nemoclaw "$SANDBOX" download /sandbox/.hermes/SOUL.md "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.hermes/state.db "$BACKUP_DIR/"
```

Exclude `/sandbox/.hermes/platforms/` and other messaging-session or pairing state from manual copies.
For normal lifecycle preservation of native messaging sessions, use [Persist Sandbox State](create-and-restore-snapshots).
For replacement sandboxes, restore channels through their supported pairing or credential setup instead of transferring sessions.

Do not copy `/sandbox/.hermes/config.yaml` or `/sandbox/.hermes/.env` between sandboxes.
The gateway, CLI, TUI, and Web Dashboard share those native files, and NemoClaw recreates their managed route and credential placeholders for the destination sandbox.
The retired reserved profile at `.hermes/profiles/dashboard-home/` is a one-time migration source, not active dashboard state.
Do not create or manually transfer that directory.
Startup removes named generated hash and runtime-state metadata, then migrates other safe legacy files and WhatsApp session state into the native Hermes home.
It removes a legacy `config.yaml` or `.env` only when its contents match the generated projection of the native files; otherwise those files merge only when the native destination is absent or byte-identical.
Conflicting or linked state stops migration without deleting either copy.

</AgentOnly>
<AgentOnly variant="deepagents">

```bash
SANDBOX=my-deepagents
BACKUP_DIR=~/.nemoclaw/backups/$(date +%Y%m%d-%H%M%S)
mkdir -p "$BACKUP_DIR"

$$nemoclaw "$SANDBOX" download /sandbox/.deepagents/config.toml "$BACKUP_DIR/"
$$nemoclaw "$SANDBOX" download /sandbox/.deepagents/agent/AGENTS.md "$BACKUP_DIR/agent/"
$$nemoclaw "$SANDBOX" download /sandbox/.deepagents/agent/memories/ "$BACKUP_DIR/agent/memories/"
$$nemoclaw "$SANDBOX" download /sandbox/.deepagents/agent/skills/ "$BACKUP_DIR/agent-skills/"
```

Do not recursively download `/sandbox/.deepagents/.state/`.
That directory can contain upstream credential state such as `auth.json` and `chatgpt-auth.json`, which can copy secrets to the host and restore state that the managed launcher refuses.
Review every downloaded path and exclude credential state from manual copies.

Do not manually transfer `/sandbox/.deepagents/.mcp.json`. Entries in that shared native file have entry-level ownership: user-authored credential-free entries belong to the workspace, while NemoClaw-managed entries contain OpenShell provider and policy bindings that are valid only for their source sandbox. Use the managed rebuild flow when native MCP entries must move with the complete native state. Run `$$nemoclaw <name> mcp migrate --apply` first if the sandbox still has legacy MCP state.

</AgentOnly>

## Upload State

Use `$$nemoclaw <name> upload` to copy files from the host into a sandbox.

<AgentOnly variant="openclaw">

```bash
SANDBOX=my-assistant
BACKUP_DIR=~/.nemoclaw/backups/20260320-120000  # pick a timestamp

$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/SOUL.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/USER.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/IDENTITY.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/AGENTS.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/TOOLS.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/HEARTBEAT.md" /sandbox/.openclaw/workspace/
```

Upload each optional memory path only when the backup contains it:

```bash
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/MEMORY.md" /sandbox/.openclaw/workspace/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/memory/" /sandbox/.openclaw/workspace/memory/
```

</AgentOnly>
<AgentOnly variant="hermes">

For Hermes, prefer [Persist Sandbox State](create-and-restore-snapshots) for normal lifecycle preservation of `state.db`.
Use manual download and upload only when you need to inspect or transfer a specific file.

```bash
SANDBOX=my-hermes
BACKUP_DIR=~/.nemoclaw/backups/20260320-120000  # pick a timestamp

$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/SOUL.md" /sandbox/.hermes/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/state.db" /sandbox/.hermes/
```

Do not upload saved `platforms/` contents, legacy messaging sessions, or other pairing state into a replacement sandbox.
Recreate and verify its messaging channels through their supported setup flow.

</AgentOnly>
<AgentOnly variant="deepagents">

```bash
SANDBOX=my-deepagents
BACKUP_DIR=~/.nemoclaw/backups/20260320-120000  # pick a timestamp

$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/agent/AGENTS.md" /sandbox/.deepagents/agent/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/agent/memories/" /sandbox/.deepagents/agent/memories/
$$nemoclaw "$SANDBOX" upload "$BACKUP_DIR/agent-skills/" /sandbox/.deepagents/agent/skills/
```

Do not upload saved `.deepagents/.state` or `.deepagents/.mcp.json` contents during manual restore.
Restore only the safe files listed above. Use managed rebuild when native MCP entries must survive replacement, so the complete native state moves with the live OpenShell policy and provider state.

Treat downloaded `config.toml` as inspection context.
Do not upload an old `config.toml` over a rebuilt sandbox unless you are intentionally replacing NemoClaw's generated route metadata.

</AgentOnly>

## Use the Source-Tree Backup Helper

<Note title="Source-tree helper script">
The [`scripts/backup-workspace.sh`](https://github.com/NVIDIA/NemoClaw/blob/main/scripts/backup-workspace.sh) helper exists only in the NemoClaw source repository for engineering workflows.
It is not installed by the standard installer. Host installs can use `nemoclaw backup-all` for the installer safety backup, or `nemoclaw <name> download` for an independent file copy.
</Note>

Run the contributor setup from the NemoClaw source repository root before you create a backup:

```bash
npm run dev:setup
```

The helper checks that the built NemoClaw CLI can start before it creates a backup.

Back up a workspace:

```bash
./scripts/backup-workspace.sh backup my-assistant
```

The helper requires `SOUL.md`, `USER.md`, `IDENTITY.md`, `AGENTS.md`, `TOOLS.md`, and `HEARTBEAT.md`.
It skips `MEMORY.md` and `memory/` when those optional paths do not exist.
It does not back up `POLICY.md`.
A backup contains six to eight items, depending on which optional paths exist.

Both optional paths exist in this example.

Expected output:

```text
Backing up workspace from sandbox 'my-assistant'...
Backup saved to /home/user/.nemoclaw/backups/20260320-120000/ (8 items)
```

If a required file cannot download, the helper deletes the new timestamped backup and exits.
The helper also deletes the backup when an optional path exists but cannot download.
Check the reported sandbox path for a symbolic link, unsupported file type, or transfer failure.
Correct the path, then run the same backup command again.

Restore the most recent backup or a specific timestamp:

```bash
./scripts/backup-workspace.sh restore my-assistant
./scripts/backup-workspace.sh restore my-assistant 20260320-120000
```

Verify the saved files:

```bash
ls -la ~/.nemoclaw/backups/20260320-120000/
```

Both optional paths exist in this example.

Expected output:

```text
AGENTS.md
HEARTBEAT.md
IDENTITY.md
MEMORY.md
SOUL.md
TOOLS.md
USER.md
memory/
```

</AgentOnly>
