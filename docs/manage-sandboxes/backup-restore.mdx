OpenShell owns the sandbox lifecycle and its native home/workspace storage. Routine stop, start, reconnect, and host gateway restart operations keep that storage in place. NemoClaw does not maintain a per-agent persistence allowlist for those operations.

## What Persists

Everything the agent writes under its OpenShell-provided native home/workspace persists as ordinary sandbox state. This includes undeclared files as well as configuration, histories, hooks, plugins, packages, cron data, skills, memory, and child-agent state.

OpenShell-owned credential stores and host-only secrets are outside the agent home/workspace. NemoClaw does not copy those stores into agent-visible state. Continue to provision credentials through supported OpenShell providers and bindings.

## Rebuild and Recreation

Most lifecycle operations do not need a backup or restore step. When `$$nemoclaw <name> rebuild` or onboarding must replace a sandbox, NemoClaw performs one bounded migration:

1. Capture the complete native home/workspace as an opaque private archive.
2. Create the replacement through OpenShell.
3. Clear the replacement's fresh native home/workspace and restore the complete archive.
4. Validate the replacement before retiring the temporary handoff.

The transfer does not sanitize, merge, or discard unknown agent paths. If the complete archive cannot be captured or restored, NemoClaw stops the replacement workflow and retains recovery information instead of publishing a partial migration.

For a stopped eligible container, NemoClaw starts it through the OpenShell lifecycle long enough to capture the workspace and then returns it to the stopped state. If it cannot restore that lifecycle state, the operation fails and reports the runtime that needs attention.

## Backup Before Upgrade

`$$nemoclaw backup-all` remains an installer-facing safety operation. It captures the same complete native home/workspace for every eligible registered sandbox before an OpenShell upgrade. It is not a general snapshot create/list/restore interface.

Backups created by older NemoClaw versions from a selective per-agent path inventory are not candidates for automatic rebuild or recreation restore. Recover files from those legacy backup directories manually, then create a current complete native-home backup before replacement.

## Destroy

`$$nemoclaw <name> destroy` asks OpenShell to delete the sandbox and its native storage. Download files you need before destroy. To replace software while preserving the complete native state, use `$$nemoclaw <name> rebuild`.
