## v0.0.139

NemoClaw v0.0.139 fixes rootless Podman cleanup for Hermes sandboxes, improves native inference recovery, reports native backup contents, and publishes compatible llama.cpp image signatures.

- Destroying a Hermes sandbox on rootless Podman now retries native-home cleanup as the image's pinned sandbox user when privileged cleanup cannot remove agent-owned files.
  If that cleanup fails, NemoClaw preserves the sandbox registry entry for a retry.
  Related change: [PR #13639](https://github.com/NVIDIA/NemoClaw/pull/13639).
- When a native inference provider is missing and only the sandbox registry records its ownership, onboarding and `nemoclaw inference set` name the affected sandbox.
  If the sandbox no longer exists, run `nemoclaw <name> destroy`, then onboard again.
  Related change: [PR #13626](https://github.com/NVIDIA/NemoClaw/pull/13626).
- `nemoclaw backup-all` now reports the directory and file counts in each successful native archive, followed by its retained path.
  Directory counts include the archive root, and file counts include symbolic links.
  Related change: [PR #13073](https://github.com/NVIDIA/NemoClaw/pull/13073).
- New llama.cpp image publications include Sigstore bundle signatures and a legacy image signature.
  The publication workflow verifies the legacy signature with Cosign 2 before it emits a receipt.
  Related change: [PR #13667](https://github.com/NVIDIA/NemoClaw/pull/13667).
